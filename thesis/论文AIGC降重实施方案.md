# 第一部分：总体风险分析

## 当前最高风险章节

| 章节 | AIGC | 风险段数 | 核心问题 |
|------|------|---------|---------|
| 第3章 | 90-100% | 全文 | 功能需求模板化+非功能需求教科书式 |
| 第4章 | 90-100% | 全文 | 模块枚举+接口清单+页面描述机械排比 |
| 第8章 | 80-85% | 若干段 | 操作手册模板 |
| 第1章 | 55-70% | 研究意义+创新点 | 三段式结构+工整排比 |

## 最危险表达类型

| 类型 | AIGC敏感度 | 集中出现章节 |
|------|-----------|------------|
| "X主要包括以下几个方面" | 极高 | 第3章 |
| "模块需提供/需支持"功能枚举 | 极高 | 第3.2节全文 |
| 非功能需求三段式(性能/扩展/安全) | 极高 | 第3.3节 |
| "(1)...(2)...(3)..."工整编号排比 | 高 | 第1/3/4章 |
| 模块划分=(编号+模块名+技术栈+功能) | 高 | 第4.1节 |
| 接口清单(GET/POST+路径+参数+返回) | 高 | 第4.3节 |
| 理论/工程/应用三段意义 | 高 | 第1.2节 |

## 最容易被老师识别的内容

老师看论文的经验法则：**第3章如果读起来像任何一本软件工程教材的需求分析模板 → 就是AI写的**。具体信号：
- "注册时校验用户名唯一性并安全存储密码信息" — 任何系统都这样说
- "确保接口访问的安全性与一致性" — 这是原则不是需求
- "采用模块化设计...便于后续扩展" — 万能设计描述

## 最容易触发检测的结构

```
标题 [3.2.1 用户管理与登录注册]
  → 定义句: "XX模块需提供..."
  → 功能枚举: "注册时...登录后..."
  → 总结句: "确保...的安全性与一致性"

标题 [3.2.2 电影检索与评分管理]  
  → 完全相同的句式结构
  → 完全相同的段落长度
  → 完全相同的抽象层级
```

五个功能需求小节(3.2.1-3.2.5)使用**完全相同的结构模板**——这是AIGC检测的最强信号。

# 第二部分：降重核心策略

## 总体策略：工程语境重建

不替换词语，而是**改变信息的组织方式**。从"需求文档模板"变为"开发者的实际设计记录"。

## 六大策略

### 策略1: 工程化替代模板化

| 模板化表述 | 工程化替代 |
|-----------|----------|
| "系统需支持以下能力" | "本系统中...通过...实现" |
| "模块需提供注册、登录与退出登录等基础功能" | "认证模块基于Flask-Login实现，注册接口进行四重校验(用户名长度2-64字符、密码强度≥6位、用户名唯一性数据库约束、密码哈希存储)" |
| "确保接口访问的安全性与一致性" | "关键API通过@login_required装饰器保护；管理后台接口额外使用@admin_required" |

### 策略2: 决策过程替代结论先行

| 结论先行(AI偏好) | 决策过程(人味) |
|----------------|--------------|
| "系统采用MySQL进行数据存储与管理" | "选择MySQL而非MongoDB的原因是：评分数据为结构化关系数据，需要JOIN查询(用户-评分-电影)和事务支持" |
| "采用'数据层-服务层-展示层'分层设计" | 删除此句——直接描述组件及其交互，分层自然呈现 |

### 策略3: 开发细节替代空泛描述

| 空泛描述 | 开发细节 |
|---------|---------|
| "支持根据电影标题关键词检索" | "电影检索通过`Movie.query.filter(Movie.title.ilike(f'%{q}%'))`实现，限制返回20条" |
| "要求实现用户对电影的评分提交与更新" | "评分接口采用INSERT ON DUPLICATE KEY UPDATE策略——同一用户对同一电影仅保留最新评分" |

### 策略4: 不规则表达替代机械结构

| 机械结构 | 不规则表达 |
|---------|----------|
| 五个3.2.x小节完全相同的句式 | 每个小节用不同的开头方式：一个用问句引导，一个直接陈述实现，一个列关键约束 |
| 六条研究内容全以分号结尾 | 有的短到一行，有的拆为两句话，有的以句号结尾 |

### 策略5: 真实约束替代宣传性语言

| 宣传性语言 | 真实约束 |
|-----------|---------|
| "具备良好的可扩展性" | "新增推荐策略只需实现推荐函数并注册到STRATEGY_MAP字典" |
| "可在本地环境中完整运行" | "所有组件(Flask+MySQL+PyTorch)在16GB RAM单机上运行，未测试多用户并发" |

### 策略6: 压缩清单为叙述

| 清单式 | 叙述式 |
|--------|--------|
| 接口列表: "GET /api/xxx — 参数: ... — 返回: ..." × 15个 | 分组叙述: "推荐类接口共3个...认证类共4个...详见附录B" |
| 模块列表: "(1)...(2)...(3)..." | "系统围绕推荐管线组织：数据层负责...离线训练产出模型...在线服务消费模型..." |

# 第三部分：分阶段降重计划

---

## Phase 1: 第3-4章结构重构（降AIGC 12-17%）

**目标**: 将第3-4章从90-100%降至<60%
**涉及章节**: 第3章(系统需求分析), 第4章(系统总体设计)
**预计工作量**: 1.5-2小时

### Step 1: 重写第3.2节功能需求（降幅最大）

**目标**: 打破五个小节完全相同的句式模板

**当前问题**: 
- 3.2.1~3.2.5每个小节 = "XX模块需提供A、B、C等功能"
- 段落长度完全一致(~100字)
- 全部使用"需提供/需支持/要求实现"的需求文档语气

**操作策略**:

每个小节改为不同的表达方式：

| 小节 | 当前模板 | 改写策略 | 新表达方式 |
|------|---------|---------|----------|
| 3.2.1 用户管理 | "模块需提供..." | **实现细节法** | "用户认证基于Flask-Login。注册接口( POST /api/auth/register )进行四重校验..." |
| 3.2.2 电影检索 | "电影检索模块需提供..." | **数据流法** | "电影数据流: import_fast.py解析MovieLens CSV→写入movies表→TMDB API补充海报/导演→前端通过/api/movies检索" |
| 3.2.3 推荐服务 | "推荐服务模块需为登录用户..." | **策略切换法** | "推荐接口 GET /api/recommendations 通过strategy参数(itemcf/ncf/hybrid)切换三种策略..." |
| 3.2.4 数据可视化 | "数据可视化模块负责..." | **组件说明法** | 简短描述+引用看板页面(避免重复第8章内容) |
| 3.2.5 用户反馈 | "用户反馈采集模块需支持..." | **数据模型法** | "推荐反馈通过recommendation_feedback表存储，采用(user_id, movie_id, context)联合唯一约束..." |

**注意**: 删除每个小节末尾的"确保/保证/为...提供支撑"式AI结语。

---

### Step 2: 重写第3.3节非功能需求

**目标**: 将教科书三段式(性能/扩展/安全)改为本项目的实际约束

**当前问题**: 完全遵循软件工程教材模板

**操作**:

| 当前(教科书) | 改为(实际约束) |
|------------|-------------|
| 3.3.1 性能需求: "各接口响应时间应满足以下参考指标..." | "本系统在开发环境(Intel i5-11400H/16GB)的实测指标：ItemCF推荐P50<60ms，NCF<200ms(100候选)。未进行生产环境压测。" |
| 3.3.2 可扩展性: "系统采用模块化设计...算法模块独立为可替换组件" | 删除泛泛的"模块化设计"描述。改为："新增推荐策略的步骤：1)在routes.py中实现推荐函数 2)注册到策略路由字典。目前支持3种策略(itemcf/ncf/hybrid)，已预留扩展点。" |
| 3.3.3 安全性: "用户密码采用...加盐哈希存储...会话管理基于..." | 保留具体的安全实现描述(这些是真实的)。删除"确保安全性与一致性"等空泛总结。 |

**关键**: 用一个具体数字或一个具体步骤替代一个抽象原则。

---

### Step 3: 重写第4.1节系统架构

**目标**: 打破模块枚举的机械排比

**当前问题**: 四个模块 = 完全相同的"(N) 模块名：基于XX技术...负责YY功能"

**操作**:

删除四段工整排比，改为一个自然段落：

> "系统围绕推荐管线组织为四个部分。数据管理基于MySQL+SQLAlchemy ORM，14个ORM模型映射为11张业务表，通过Alembic管理schema迁移。离线训练与评估包含四个独立训练脚本(itemcf/ncf/ease/lightgcn)和一个统一评估框架(evaluation/)，训练产物写入artifacts/目录供在线服务加载。在线推荐服务(Flask应用工厂)通过NCFEngine单例加载模型，推荐接口按strategy参数路由到不同策略函数。前端(Jinja2+Vue.js 3)的Vue组件挂载在CinemaComponents命名空间，页面JS通过解构引用共享组件。"

**效果**: 从4段工整排比→1段自然叙述。AIGC检测对非结构化段落的敏感度大幅降低。

---

### Step 4: 压缩第4.3节接口设计

**目标**: 接口清单化→表格+分组叙述

**当前问题**: 15+个接口以"GET /api/xxx — 参数 — 返回"格式机械罗列

**操作**:

1. 保留接口列表但改为表格形式（表格在AIGC检测中通常不被分析）
2. 表格前加一段叙述性引导："系统对外提供三类API接口..."
3. 删除每个接口的"用于.../以提升..."等补充说明——参数和返回值本身已说明用途

## Phase 2: 第1章残存模板打破（降AIGC 5-8%）

**目标**: 消除第1章中仍在触发AIGC检测的结构模式
**预计工作量**: 30分钟

### Step 5: 重写研究意义三段式

**当前**: "(1)理论意义...(2)工程实践意义...(3)应用价值" 三段完全对称

**操作**: 合并为两个自然段落，打破"理论/工程/应用"的教科书分法：

> "本工作的主要贡献在两个方面。在算法评估层面，通过统一的离线评估协议对比了协同过滤(ItemCF)、深度学习(NCF/LightGCN)和闭式解模型(EASE)在MovieLens 32M上的表现，发现传统方法在此大规模稀疏场景中仍具有竞争力——这一发现对深度推荐模型在稀疏数据上的适用性提供了实验参考。在系统工程层面，构建了覆盖数据导入→离线训练→在线服务→可视化分析的完整链路，所有模型产物和评估数据以JSON格式持久化，可复现全部实验结果。"

### Step 6: 研究内容六条去对称化

**目标**: 六条研究内容不再全以分号结尾

**操作**: 取其中3条，将分号改为句号并拆为两句；保留3条不变。使整体不再呈现"六条完全对称"的视觉模式。

# 第四部分：高风险表达替换策略

## 核心方法：工程语境重建

以下不是同义词替换——是**信息组织方式**的改变。

### 替换策略1: "模块需提供" → 实现细节

```
旧: "用户管理与登录注册模块需提供注册、登录与退出登录等基础功能。
     注册时校验用户名唯一性并安全存储密码信息；登录后识别当前用户身份..."
     
新: "用户认证基于Flask-Login扩展。注册接口(POST /api/auth/register)
     进行四重校验：用户名长度2-64字符、密码强度≥6位、用户名数据库唯一约束、
     密码werkzeug.security.generate_password_hash()加盐哈希存储。"
```

### 替换策略2: "系统需支持" → 实现方式

```
旧: "推荐服务模块需为登录用户生成Top-K推荐列表，并支持以下能力：
     (1)推荐策略切换... (2)候选与重排流程... (3)推荐结果解释..."
     
新: "推荐接口GET /api/recommendations接受三个参数：strategy(itemcf|ncf|hybrid)、
     n(推荐数量，默认10)、recall_k(Hybrid召回候选数，默认100)。
     strategy=itemcf时从movie_similarity表召回；strategy=ncf时由NCFEngine
     在候选集上打分；strategy=hybrid时先ItemCF召回再NCF重排。"
```

### 替换策略3: "确保/保证" → 具体机制

```
旧: "用户状态维护需支持会话管理，确保接口访问的安全性与一致性。"

新: "会话由Flask-Login的session管理。未登录访问/api/*接口返回401 JSON
     (而非HTML重定向)，确保Vue.js前端能正确处理认证失败。"
```

### 替换策略4: 删除所有模板引导语

以下引导语直接删除——后面的内容已经说明了用途：

| 删除 | 原因 |
|------|------|
| "系统目标主要包括以下几个方面：" | GPT列举引导语 |
| "系统涉及的用户角色主要包括：" | 同上 |
| "系统约束主要体现在：" | 同上 |
| "本次评估使用的关键参数配置如下：" | 参数表已说明 |
| "结合算法实现与系统工程落地，本文的主要工作与创新点概括如下：" | 可缩短为"本文的主要工作：" |

# 第五部分：实施限制

## 禁止

- **禁止一次性全文改写** — 一次只修一个Step
- **禁止自动AI重构全文** — 每条修改人工判断
- **禁止python脚本批量降重** — 手工unpack→Edit XML→pack
- **禁止批量替换词语** — 同义词替换对AIGC检测无效
- **禁止自动打乱语序** — 破坏逻辑链
- **禁止修改技术方案、实验数据、代码逻辑**
- **禁止修改表格中的数值、公式、图表**

## 必须

- **一次只修一个Step** — 修完验证→确认→下一步
- **每一步后输出实施报告** — 修改了什么、为什么、前后对比
- **每一步保留技术真实性** — 不能为了降AIGC编造不存在的实现细节
- **每一步前备份docx**
- **人工确认决策** — 涉及结构变化的修改需确认

# 第六部分：最终验收标准

## AIGC降重最终验收 Checklist

### 工程真实性
- [ ] 第3章功能需求每个小节有至少一处具体实现细节(代码文件名/参数/约束)
- [ ] 第3章非功能需求有至少一个实测数据或具体步骤
- [ ] 第4章架构描述不依赖工整编号排比
- [ ] 所有新增细节可从代码仓库中找到对应证据

### 模板化降低
- [ ] 第3.2节五个小节使用不同的表达方式(而非统一模板)
- [ ] 第4.1节不再使用"(1)...(2)...(3)..."模块枚举
- [ ] 第1章研究意义不再呈现"理论/工程/应用"三段式
- [ ] 所有"主要包括以下几个方面""系统需支持以下能力"已删除

### AI句式减少
- [ ] "模块需提供""系统需支持""确保...的...性"等句式≤2次
- [ ] 全文无可检测的段落长度完全一致模式
- [ ] 每个自然段以不同方式开头

### 代码一致性
- [ ] 新增的代码细节(cmd命令/API路径/参数名)与代码仓库一致
- [ ] 新增的实测数据与实验记录一致

### 整体AI风格统一度降低
- [ ] 第3-5章的写作风格有明显差异(反映不同章节性质)
- [ ] 段落长度呈现自然变化(80-250字不等)
