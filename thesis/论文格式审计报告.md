# 论文格式审计报告

**审计对象**：`thesis/毕业论文.working.docx`
**审计日期**：2026-05-28
**审计依据**：《青岛理工大学毕业设计说明书（论文）撰写规范格式》
**审计方法**：基于 Word 原生 XML 结构（样式系统、段落属性、页面设置），逐项对比学校规范

# 2. 关键问题摘要

以下问题最可能影响毕业答辩/查重/格式审核：

1. **[CRITICAL] 第7章标题使用手动格式而非样式**：第7章"总结与展望"在正文中使用了手动加粗（SimHei + Bold + 16pt），未应用"每章标题"样式，导致该标题不会出现在自动目录中，且与其他7章格式不一致。

2. **[CRITICAL] 1166个段落无样式（直接格式）**：全文约1166个段落的 `w:pStyle` 为空，全部依赖直接格式覆盖。这导致样式体系形同虚设、批量修改无法进行、格式一致性无法保证。

3. **[CRITICAL] 章/节/小节样式缺少大纲级别**：自定义样式"每章标题"、"节标题（章下）"、"小节"均未设置 `outlineLvl` 属性。这导致 Word 自动目录无法识别这些标题，目录更新后将丢失全部标题。

4. **[HIGH] "目录"标题使用内置 TOC Heading 样式**：根据规范，目录标题应为"小二号黑体，居中"。"目录"二字当前使用 Word 内置 `TOC` 样式（outline level 9），不符合中文论文排版规范。

5. **[HIGH] 自定义样式名不符合中文 Word 命名规范**：样式名"毕设正文"、"每章标题"等为拼音/混合命名，Word 样式管理器显示混乱，且与 Word 内置的"标题1/2/3"体系无法配合。

6. **[HIGH] 参考文献数量不足**：共22条参考文献，其中外文仅12条（英文），中文10条。学校要求"参考文献不少于8篇，其中外文文献不少于2篇"——数量满足，但缺少近3年（2023-2026）文献，文献时效性分布不佳。

# 3. 分模块详细审计

## 一、论文整体结构审计

### 问题 1.1 — 第7章标题未使用样式
- **严重等级**：Critical
- **所在章节/页**：第7章，约第60页
- **问题描述**：第7章"总结与展望"（正文标题）使用直接手动格式（SimHei 16pt Bold），样式为 `None`，而非 `aff9`（每章标题）。其他7章均正确使用了 `aff9` 样式。
- **影响**：该标题不会出现在自动目录中；若更新目录域，第7章将从目录消失；打印/导出PDF后与其他章节标题视觉上可能不一致。
- **修复建议**：选中该段落，应用"每章标题"（aff9）样式。
- **是否需人工确认**：否，直接应用样式即可。

### 问题 1.2 — 2.5.2节末尾混入下一节标题
- **严重等级**：High
- **所在章节/页**：第2章 2.5.2节，约第10-11页
- **问题描述**：正文"2.5.2 排序类指标（NDCG@K、MRR@K）"的末尾段落直接拼接了"2.6 LightGCN与EASE模型"的完整内容，包括两个模型的原理解释（MRR@K段落后直接跟LightGCN介绍）。这在目录中找不到2.6节——它被藏在2.5.2最后一段。
- **影响**：目录不完整，缺少2.6节；读者无法通过目录定位LightGCN/EASE介绍；论文结构不清晰。
- **修复建议**：将"2.6 LightGCN与EASE模型"拆分为独立的节标题（应用"节标题（章下）"样式），并在目录中更新。
- **是否需人工确认**：是，需确认2.6节标题应如何命名及位置。

### 问题 1.3 — 5.7节下子节层级混乱
- **严重等级**：Medium
- **所在章节/页**：第5章 5.7节，约第44页
- **问题描述**：5.7节标题"前端核心实现"使用了"节标题（章下）"样式（affb），但其下5.7.1-5.7.4却使用"小节"样式（affd）。而在目录中，5.7被列为节标题，5.7.x被列为第三级。这与第5章其他部分一致（5.1-5.5各有子节），但5.7作为"前端核心实现"的归类，逻辑上应该独立成节或合并到5.6中。
- **影响**：第5章结构略不均衡（5.6有7个子节，5.7有4个子节），但严格来说不违反规范。
- **修复建议**：保持现状或考虑将5.7合并为5.6.8，视整体结构安排。
- **是否需人工确认**：是。

### 问题 1.4 — 论文宣称7章但实际有8章
- **严重等级**：Medium
- **所在章节/页**：第1章 1.4节，第6页
- **问题描述**：1.4节"论文组织结构"中写明"本文共分为七章"，但实际论文包含8章（第8章为系统使用指南）。目录中有第8章。
- **影响**：前后不一致，答辩时可能被指出。
- **修复建议**：将"七章"改为"八章"，并在1.4节的章节目录描述中补充第8章内容。
- **是否需人工确认**：否。

### 问题 1.5 — 分节符设置
- **严重等级**：Low
- **所在章节/页**：全文档
- **问题描述**：文档使用连续分节符（共5个Section），未使用下一页分节符分隔章。各章之间依靠手动换页或段落间距实现分页，而非通过分节符控制。封面/Section 0 设置了 titlePg 属性。
- **影响**：目前视觉效果可能正常，但文档结构不够稳固——若调整纸张大小或边距，章起始位置可能漂移。
- **修复建议**：建议每章开头使用分页符或"段前分页"属性，而非依赖空白段落。
- **是否需人工确认**：是。

## 二、Word 样式体系审计

### 问题 2.1 — 1166个段落无样式
- **严重等级**：Critical
- **所在章节/页**：全文档
- **问题描述**：全文1166个段落（约占总段落数的76%）的 `w:pStyle` 为空，使用直接格式指定字体、大小、对齐等属性。即使定义了"毕设正文"（afff）、"每章标题"（aff9）等自定义样式，绝大部分正文段落并未使用它们。
- **影响**：样式体系完全失效；无法通过修改样式统一全文档格式；校方格式审查时会发现正文格式不统一；修改一处需要手动逐段修改。
- **修复建议**：对全文正文段落统一应用"毕设正文"样式；对章/节/小节标题统一应用对应样式；清除多余的直接格式。
- **是否需人工确认**：否。建议使用 Word 的"选择所有格式相似的文本"功能逐步替换。

### 问题 2.2 — 自定义样式缺少大纲级别
- **严重等级**：Critical
- **所在章节/页**：全文档样式定义
- **问题描述**：自定义样式"每章标题"（aff9）、"节标题（章下）"（affb）、"小节"（affd）均未在 `<w:pPr>` 中定义 `<w:outlineLvl>`。Word 的内置样式"heading 1/2/3"有正确的 outline level（0/1/2），但自定义样式没有继承此属性。
- **影响**：Word 自动目录功能无法识别这些标题；目录更新后将变为空白或仅显示"目录"二字；导航窗格不显示自定义标题。
- **修复建议**：在 styles.xml 中为 `aff9` 添加 `<w:outlineLvl w:val="0"/>`，为 `affb` 添加 `w:val="1"`，为 `affd` 添加 `w:val="2"`。
- **是否需人工确认**：是。修改 styles.xml 需解包 DOCX，编辑后重新打包。

### 问题 2.3 — 样式"基于"链断裂
- **严重等级**：High
- **所在章节/页**：样式定义（styles.xml）
- **问题描述**：
  - "每章标题"（aff9）基于 "heading 1"（1），但 heading 1 基于 "Normal"（a1）
  - "节标题（章下）"（affb）基于 "heading 2"（21），继承链正常
  - "小节"（affd）基于 "heading 3"（31），继承链正常
  - 但是"毕设正文"（afff）基于 "Normal"（a1），而 Normal 没有首行缩进——因此应用 afff 样式后也不会自动有首行缩进，需要依赖样式中定义的 firstLine=480。
- **影响**：样式继承链存在，但实际应用效果可能因 basedOn 样式的默认属性而不一致。
- **修复建议**：确保所有基于的样式具有合理的默认值；核实样式继承是否符合预期。
- **是否需人工确认**：是。

### 问题 2.4 — 正文样式覆盖率低
- **严重等级**：High
- **所在章节/页**：全文档
- **问题描述**：定义了"毕设正文"样式（SimSun + Times New Roman, 12pt, 两端对齐, 1.5倍行距, 首行缩进480 DXA），但实际使用时仅有87个段落应用了该样式。大量正文段落使用直接格式，包括：
  - 975个 Run 使用 Times New Roman/SimSun（与"毕设正文"一致）
  - 364个 Run 使用纯 SimSun
  - 205个 Run 使用微软雅黑（不在规范要求中）
- **影响**：正文格式不统一；若需调整全文字体、行距或缩进，需要逐段修改。
- **修复建议**：对所有正文段落批量应用"毕设正文"样式。
- **是否需人工确认**：否。

### 问题 2.5 — "目录"使用原始内置样式
- **严重等级**：High
- **所在章节/页**：目录页
- **问题描述**：目录标题"目录"使用 Word 内置 `TOC` 样式（TOC Heading, outline level 9），而非自定义的中文论文样式。这与其他一级标题（使用每章标题样式）不一致。`TOC` 样式作为目录标题可能使用不同的字体和字号。
- **影响**："目录"二字的格式可能与其他一级标题不一致。
- **修复建议**：将"目录"改为应用"每章标题"样式，或单独定义"目录标题"样式。
- **是否需人工确认**：否。

### 问题 2.6 — 正文段落字体不一致
- **严重等级**：High
- **所在章节/页**：全文档
- **问题描述**：正文在三种字体间切换：
  - 宋体（SimSun）：364个Run
  - Times New Roman + 宋体：975个Run
  - 微软雅黑：205个Run
  - MS Mincho（日语明朝体）：156个Run（疑似来自公式中的数学符号渲染）
  学校规范要求中文摘要和正文使用宋体（小四号），英文使用 Times New Roman，不应出现微软雅黑和 MS Mincho。
- **影响**：字体不统一影响版式美观，学校格式审查可能指出字体不一致问题。
- **修复建议**：
  - 微软雅黑段落 → 统一改为宋体（SimSun）
  - MS Mincho → 排查是否来自公式编辑器或第三方软件（如 MathType），如为公式则保留，如为正文则改为 Times New Roman
- **是否需人工确认**：是（MS Mincho 来源需确认）。

### 问题 2.7 — 正文中小四号字体大小不一致
- **严重等级**：Medium
- **所在章节/页**：全文档
- **问题描述**：正文中字体大小存在3种：
  - 9pt（18半磅）：956个Run——这是正文主体
  - 12pt（24半磅）：234个Run
  - 10.5pt（21半磅）：184个Run
  规范要求正文为"小四号宋体"（12pt）。当前9pt占比最高，说明正文实际使用五号而非小四号。
- **影响**：与学校规范不符，小四号=12pt，当前9pt偏小约25%。
- **修复建议**：将正文字体统一调整为12pt（小四号）。
- **是否需人工确认**：否。

## 三、页面与排版审计

### 问题 3.1 — 行距可能不符合规范
- **严重等级**：Medium
- **所在章节/页**：全文档
- **问题描述**：当前行距为 `line=360, lineRule=auto`（1.5倍行距），规范要求正文行距应统一（虽未明确规定行距值，但本科论文通常使用1.5倍行距）。378个段落使用了360行距设置，而有部分表格/公式区域行距为 `line=440, lineRule=exact`（固定值22pt）或不设行距。
- **影响**：表格区域、公式区域和正文的行距不一致。
- **修复建议**：统一行距规则；对于有公式的段落，可使用固定行距22pt避免公式裁切。
- **是否需人工确认**：是。

### 问题 3.2 — 174个空段落
- **严重等级**：Medium
- **所在章节/页**：全文档
- **问题描述**：全文存在174个仅有空白字符的段落（`<w:t>` 内容为空或仅含空格）。这些空段落可能用于手动换行或分隔，但增加了排版的不确定性。
- **影响**：可能导致页面底部出现多余空白；在不同Word版本或PDF导出后布局可能变化。
- **修复建议**：将空段落替换为段前/段后间距设置；删除不必要的空白段落。
- **是否需人工确认**：是（需要逐一确认哪些空白是有意的）。

### 问题 3.3 — 首行缩进不一致
- **严重等级**：Medium
- **所在章节/页**：全文档
- **问题描述**：238个段落设置了 `firstLine=480`（首行缩进2字符/约8.5mm），但68个段落设置了 `left=480`（整体左缩进而非首行缩进），23个段落明确设置了 `firstLine=0`（无缩进）。大量未使用样式的段落完全依赖直接格式设置缩进。
- **影响**：正文段落缩进不统一；部分段落可能没有正确的首行缩进。
- **修复建议**：通过"毕设正文"样式统一设置首行缩进，清除直接格式覆盖。
- **是否需人工确认**：否。

### 问题 3.4 — 页边距设置
- **严重等级**：Low
- **所在章节/页**：全文档
- **问题描述**：页边距统一为 top=1417, bottom=1417, left=1417, right=1417 DXA（约2.5cm/1英寸），符合A4纸常规设置。
- **影响**：无明显问题。
- **修复建议**：无。
- **是否需人工确认**：否。

## 四、标题体系审计

### 问题 4.1 — 标题编号为手动输入
- **严重等级**：Critical
- **所在章节/页**：全部章/节/小节
- **问题描述**：所有"第X章"、"X.X"、"X.X.X"编号均为手动输入的文字，而非 Word 多级列表自动编号。段落中 `numPr` 元素总数为0（无任何自动编号）。
- **影响**：无法使用 Word 的自动编号功能；增删章节后需手动重新编号所有后续章节；容易出错。
- **修复建议**：将所有标题改为 Word 多级列表自动编号，与样式"每章标题/节标题（章下）/小节"关联。
- **是否需人工确认**：是。改为自动编号后需重新生成目录。

### 问题 4.2 — "致谢"、"参考文献"、"附录"作为章标题
- **严重等级**：Medium
- **所在章节/页**：致谢（约第83页）、参考文献（约第84页）、附录（约第86页）
- **问题描述**："致 谢"、"参考文献"、"附 录"均使用了"每章标题"（aff9）样式，但它们在目录中没有章节编号。这在逻辑上可接受（它们不属于正文章节），但 Word 中若启用自动编号，它们可能被编号为"第9章 致谢"。
- **影响**：如果用自动编号需额外处理这些特殊标题。
- **修复建议**：为致谢/参考文献/附录单独定义样式，或在自动编号中排除它们。
- **是否需人工确认**：是。

## 五、目录审计

### 问题 5.1 — 可能为手动目录
- **严重等级**：High
- **所在章节/页**：目录页
- **问题描述**：目录区域的每个条目均为 `<w:hyperlink>` 元素（共约200个超链接），页面内容为静态文本+超链接。虽然超链接指向对应标题的锚点，但没有检测到 Word TOC 域代码（`<w:instrText>TOC</w:instrText>`）的证据。这表明目录可能是"半自动"的——由 Word 生成后固定为静态文本。
- **影响**：目录可能无法通过"更新域"自动刷新页码和标题；增删内容后需重新生成目录。
- **修复建议**：在正文标题修正后，删除当前目录内容，插入新的自动目录（引用→目录→自动目录）。
- **是否需人工确认**：否。

### 问题 5.2 — 目录中缺少2.6节标题
- **严重等级**：High
- **所在章节/页**：目录
- **问题描述**：目录中不包含"2.6 LightGCN与EASE模型"，因为该内容被嵌入在2.5.2节的末尾段落中（见问题1.2）。
- **影响**：目录不完整。
- **修复建议**：分离2.6节后重新生成目录。
- **是否需人工确认**：否。

### 问题 5.3 — 目录页码未经验证
- **严重等级**：Medium
- **所在章节/页**：目录
- **问题描述**：由于目录为静态内容，无法确认所有页码与正文实际页码一致。特别是第7章手动格式的标题，其在目录中的锚点 `_Toc230874922` 可能无法正确关联。
- **影响**：打印后读者可能发现目录页码与正文不符。
- **修复建议**：修复标题样式后重新生成目录，逐章核对页码。
- **是否需人工确认**：是。

## 六、字体与中英文混排审计

### 问题 6.1 — 微软雅黑字体入侵
- **严重等级**：High
- **所在章节/页**：全文档，共205个Run
- **问题描述**：微软雅黑不是学校规范要求的字体（规范要求中文宋体/黑体/楷体，英文 Times New Roman）。微软雅黑出现在多处正文中，可能是从网页或其他文档复制粘贴时带入。
