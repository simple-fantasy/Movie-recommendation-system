## 二、AIGC检测机制推测

### 2.1 为什么第3章和第4章 AIGC率极高(90-100%)

基于AIGC检测原理和论文文本特征分析，以下因素共同导致极高AIGC判定：

**原因1: 功能需求清单化**

第3章的核心模式：每个功能模块 = "模块名 + 需提供/需支持 + 功能枚举"

```
"用户管理与登录注册模块需提供注册、登录与退出登录等基础功能。
注册时校验用户名唯一性并安全存储密码信息；登录后识别当前用户身份，
为其提供个性化推荐、历史评分记录与画像统计等功能。"
```

这是**最典型的AI需求文档模板**——GPT生成需求分析的默认模式。AIGC检测器对这种"定义→作用→组成"句式高度敏感。

**原因2: 非功能需求教科书化**

第3.3节完全遵循软件工程教材的标准模板：
```
性能需求 → 可扩展性与可维护性 → 安全性与可靠性
```

每个子节都是"概念定义 + 本系统的实现方式"。这种结构在成千上万的AI生成文档中出现过，检测器对其极为敏感。

**原因3: 模块枚举 + 抽象归纳**

第4.1节的系统模块划分：
```
（1）数据管理模块：基于MySQL实现...通过SQLAlchemy ORM...
（2）离线训练与评估模块：包含...
（3）在线推荐服务模块：基于Flask...
（4）前端展示模块：采用Jinja2...
```

每个模块 = "编号 + 模块名 + 技术栈 + 功能描述"——高度一致的模板。

**原因4: 接口清单化**

第4.3节的接口设计：`GET/POST + 路径 + 参数 + 返回` 的机械罗列。这虽然是API文档的标准格式，但AIGC检测器无法区分"真实的API文档"和"AI生成的API文档"——它只看到高度结构化的列表。

**原因5: 缺少真实决策过程**

全文第3-4章没有一个地方写到：
- "最初考虑过X方案，但因为Y原因放弃了"
- "数据库表Z字段设计经历了3次修改"
- "接口参数N的默认值经过了压测调整"

缺少这种"人类决策痕迹"是AIGC检测器的核心判定依据之一。

### 2.2 为什么第1章（已降重改写）仍然被标红

即使我们在前次降重中将文献综述改写为技术选型理由，AIGC检测仍然将其标红。原因：

1. **"本文选择X基于以下考虑"句式**——虽然比文献堆叠好，但这仍然是AI偏好的"论证模板"
2. **三段式结构**——"第一...第二...第三..."被AIGC检测器识别为AI生成模式
3. **研究意义三段式**——"理论意义/工程实践意义/应用价值"是AI论文的经典结构

### 2.3 AIGC检测器的核心判定特征

基于标红段分析，检测器主要关注：

| 特征 | 敏感度 | 在本文中的出现 |
|------|--------|-------------|
| 工整的编号排比("(1)...(2)...(3)...") | 极高 | 全文大量使用 |
| "系统需支持/模块需提供/应具备" | 极高 | 第3章全文 |
| "主要包括以下几个方面" | 高 | 多处 |
| 定义→作用→优势三段式 | 高 | 第2章+第5章 |
| 无工程决策过程 | 高 | 第3-4章 |
| 教科书式概念定义 | 中高 | 第3.3节 |
| 三段式意义陈述 | 高 | 第1章研究意义 |
| 致谢模板 | 中 | 致谢 |

## 三、AI语言模式审计

### 3.1 高频AI句型（标红段中提取）

| AI句型 | 出现次数 | 示例 |
|--------|---------|------|
| "X主要包括以下几个方面" | 多次 | "系统目标主要包括以下几个方面" |
| "能够/可以/支持 + 动词" | 极多 | "能够依据""支持切换""可以查看" |
| "通过...实现/完成" | 高频 | "通过TMDB API补充""通过Dashboard展示" |
| "具备/具有 + 形容词 + 的 + 名词" | 高频 | "具备较好的可解释性" |
| "为...提供/奠定/支撑" | 中频 | "为系统的可用性与可扩展性提供支撑" |
| "采用...对...进行..." | 高频 | "采用MySQL对数据进行持久化管理" |

### 3.2 高频危险词

| 词汇 | AIGC敏感度 | 出现章节 |
|------|-----------|---------|
| "支持"（作为功能动词） | 极高 | 第3章密集 |
| "提供" | 高 | 全文 |
| "实现" | 高 | 全文 |
| "基于" | 中高 | 全文 |
| "通过" | 中 | 全文 |
| "确保" | 中高 | 第3章 |
| "灵活" | 高 | 多处 |
| "扩展"（"可扩展性"） | 高 | 第3章+第7章 |

### 3.3 最危险表达方式（AIGC检测极易命中）

1. **"系统需支持以下能力："** → GPT需求文档的标准开头
2. **"具备良好的......能力"** → AI万能描述模板
3. **"主要包括以下几个方面"** → GPT列举的标准引入语
4. **"(1)...；(2)...；(3)..."** 工整分号排比 → AI的结构偏好
5. **"形成......的完整闭环"** → GPT总结套话
6. **"确保......的安全性与一致性"** → AI安全描述模板
