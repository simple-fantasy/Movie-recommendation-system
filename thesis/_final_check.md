# 摘 要 {#摘-要 .中文摘要}

本文围绕电影推荐场景中的信息过载与个性化需求，设计并实现了一套面向大规模评分数据的多策略电影推荐系统CineMatch。系统以MovieLens
32M数据集为基础（包含3200万条评分记录，覆盖27万用户与8.7万部电影），采用MySQL进行数据存储与管理，基于Flask应用工厂模式构建后端服务并提供推荐接口与数据统计接口，前端采用Jinja2模板引擎与Vue.js
3混合架构，结合Bootstrap
5与ECharts实现推荐结果展示、用户画像与可视化分析。算法层面，本文实现了三种推荐策略：基于物品的协同过滤（Item-based
Collaborative
Filtering，ItemCF）作为主召回模型，通过余弦相似度与用户均值归一化计算电影间相似度并保留TopK近邻，支持可解释推荐理由生成；神经协同过滤模型（Neural
Collaborative
Filtering，NCF）基于PyTorch实现MLP架构，通过异步加载与单例模式进行高效推理；混合推荐策略（Hybrid）采用\"ItemCF召回+NCF重排\"的级联架构。系统还实现了用户画像分析（12维特征）、用户行为追踪、推荐反馈收集、数据可视化看板和管理后台等完整功能模块。为验证方法有效性，本文建立基于三层时间切分的离线评估协议，在统一候选集C_all上对8个模型进行全量排序对比，使用Precision@10、Recall@10、NDCG@10、MRR@10和Coverage等指标进行评估。实验结果表明，在MovieLens
32M数据集上，传统协同过滤方法（ItemCF）在排序精度上表现最优（NDCG@10=0.049），深度学习方法（NCF、LightGCN）在此大规模稀疏场景中未超越传统方法；EASE以闭式最小二乘解实现了精度与覆盖率的最佳平衡（Coverage=0.658，为ItemCF的6.4倍）；混合推荐策略相较纯NCF在R@10上提升了3.9%，验证了召回-重排架构对候选集排序的优化潜力，但整体效果仍受限于召回阶段质量。消融实验发现per_seed_limit=10、recall_k=50为最优参数取值。

关键词：电影推荐系统; 协同过滤; 神经协同过滤; 混合推荐; 可解释推

# ABSTRACT {#abstract .英文摘要}

To address information overload and meet personalization demands in
movie consumption, this thesis designs and implements a multi-strategy
movie recommendation system named CineMatch. Based on the MovieLens 32M
dataset---comprising 32 million ratings from 270,000 users on 87,000
movies---the system leverages MySQL for data storage and management,
employs the Flask application factory pattern for backend services and
RESTful APIs, and integrates Jinja2 templates with Vue.js 3, Bootstrap
5, and ECharts on the frontend to deliver recommendation displays, user
profiling, and visual analytics.

At the algorithmic level, three recommendation strategies are
implemented. Item-based Collaborative Filtering (ItemCF) serves as the
primary recall model, computing movie similarities through cosine
similarity with user-mean normalization and retaining only Top-K
neighbors to improve storage efficiency and retrieval speed; it also
supports explainable recommendations by identifying which previously
liked movies contributed to each suggestion. A Neural Collaborative
Filtering (NCF) model, built with PyTorch, implements an MLP
architecture with asynchronous loading and a singleton inference engine
for efficient candidate reranking. The Hybrid strategy combines both
through a cascade architecture: ItemCF generates recall candidates, and
NCF reranks them to produce the final Top-N list, balancing accuracy
with interpretability. Beyond the core recommendation pipeline, the
system includes comprehensive functional modules such as 12-dimensional
user profiling, asynchronous behavior tracking, recommendation feedback
collection, movie list creation, data visualization dashboards, and an
admin panel.

To validate recommendation quality, a unified offline evaluation
framework based on the Leave-Last-Out protocol is established, comparing
the three strategies across five ranking-oriented metrics---Precision@K,
Recall@K, MAP@K, NDCG@K, and MRR@K---supplemented by coverage and
popularity bias analyses. Ablation studies examine the effects of key
parameters such as recall candidate size and per-seed similarity limits.
The overall system demonstrates basic usability as a local
recommendation service. Experimental results indicate that on the
MovieLens 32M dataset, traditional collaborative filtering (ItemCF)
achieves the best ranking accuracy (NDCG@10=0.049), while deep learning
methods (NCF, LightGCN) do not surpass traditional approaches in this
large-scale sparse scenario. EASE achieves the best accuracy-coverage
tradeoff (Coverage=0.658, 6.4x that of ItemCF), and the Hybrid cascade
improves R@10 by 3.9% over pure NCF but remains constrained by
recall-stage quality. Ablation studies identify per_seed_limit=10 and
recall_k=50 as optimal parameter settings.

**KEY WORDS: movie recommendation system, collaborative filtering,
neural collaborative filtering, hybrid recommendation, explainable
recommendation, user profiling**

        1.  [[]{#_Toc230939974 .anchor}研究背景](#摘-要)

[电影推荐是推荐系统领域的经典应用场景。Netflix、IMDb等平台拥有数十万部电影资源，传统的排行榜和编辑推荐方式难以兼顾用户的个体兴趣与长尾内容的曝光。利用用户历史评分数据构建个性化推荐模型，是解决这一问题的有效途径。](#摘-要)

[电影推荐面临两个主要挑战。一是用户偏好的差异性：不同用户的题材偏好、年代偏好和评分尺度差异较大，近期观影行为对即时推荐的影响往往大于远期历史。二是评分数据的稀疏性：以MovieLens
32M数据集为例，评分密度约为0.14%（3200万/(27万×8.7万)），大量电影的评分次数较少，模型需要在覆盖率与准确率之间权衡。](#摘-要)

[协同过滤算法能够直接利用用户-物品交互信息挖掘相似性，是推荐系统中应用最广泛的经典方法之一。其中，基于物品的协同过滤（Item-based
Collaborative
Filtering，ItemCF）由于具备较好的可解释性、工程实现简单、在线计算效率高等特点，常被用于推荐候选集召回。然而，协同过滤方法在表示能力上存在上限，难以充分刻画复杂的非线性偏好关系。深度学习推荐模型通过Embedding与神经网络结构增强了特征表达能力，在排序精度方面表现突出，但其训练与推理成本相对较高，更适合用于候选集的精排或重排阶段。因此，\"召回-重排\"的两阶段混合推荐框架在工业界被广泛采用。](#摘-要)

[本文以MovieLens
32M数据集为基础，使用MySQL进行数据管理，基于Flask构建后端服务。算法层面实现ItemCF作为召回模型、NCF（MLP架构）作为重排模型，以\"ItemCF召回→NCF重排\"的级联方式构建Hybrid管道。此外，本文还引入了EASE（闭式最小二乘模型）和LightGCN（轻量图卷积模型）作为外部对比方法，用于评估不同算法范式在MovieLens
32M数据集上的表现差异。系统还包括用户画像（12维特征）、行为追踪、收藏评论和管理后台等功能。为验证各模型效果，本文建立了三层时间切分离线评估协议，在统一候选集C_all上对8个模型进行全量排序对比，并通过消融实验分析关键参数的影响。](#摘-要)

2.  [ []{#_Toc230939976 .anchor}国内外研究现状](#摘-要)

    1.  

[[]{#_Toc230939977
.anchor}协同过滤与ItemCF研究现状协同过滤（Collaborative
Filtering，CF）是推荐系统领域应用最广泛的经典方法之一，其核心思想是利用用户-物品交互行为中的相似性来预测用户偏好。根据建模对象的不同，协同过滤主要分为基于用户的协同过滤（UserCF）与基于物品的协同过滤（ItemCF）。其中，ItemCF通过度量物品之间的相似度\[1\]，将用户历史偏好的物品映射到相似物品集合，从而生成推荐结果\[8\]。相较于UserCF，ItemCF在用户规模较大且用户兴趣相对稳定的场景中往往具有更好的在线效率与更高的稳定性，并且其推荐原因可以通过\"与用户喜欢的某些物品相似\"进行解释，因而在工程落地中得到广泛应用。](#摘-要)

[在相似度计算方面，常见方法包括余弦相似度、皮尔逊相关系数、Jaccard系数等\[1,3\]。针对评分数据，研究者通常会引入评分归一化、惩罚热门物品、时间衰减等机制以缓解数据稀疏与流行度偏置对相似度估计的影响。其中，用户均值归一化（调整余弦相似度）通过将评分减去用户均值，能够有效消除\"宽容型用户\"与\"苛刻型用户\"之间的系统偏差，提高相似度计算的准确性。另一方面，随着数据规模增大，直接构建完整的物品-物品相似矩阵将带来的存储与计算开销。为此，TopK近邻截断、倒排索引、近似最近邻检索（ANN）等方法被广泛用于提升ItemCF在大规模数据上的可用性。总体而言，ItemCF具备实现简单、可解释性强与在线开销可控等优势，但其表达能力主要依赖于相似度度量方式，难以捕获更复杂的非线性偏好关系，在排序精度方面存在一定上限。](#摘-要)

1.  [[]{#_Toc230939978 .anchor}深度学习推荐与NCF研究现状](#摘-要)

[近年来，深度学习技术在计算机视觉、自然语言处理等领域取得进展，也推动了推荐系统从传统特征工程与浅层模型向表示学习与端到端训练方向发展。深度学习推荐模型通常通过Embedding将离散的用户与物品映射为稠密向量，再通过神经网络结构建模用户偏好与物品特征之间的复杂关系，从而提升模型表达能力与排序效果。典型模型包括基于多层感知机（MLP）的点击率预估模型、基于序列建模的推荐模型以及图神经网络推荐模型等\[7,14\]。](#摘-要)

[神经协同过滤（Neural Collaborative
Filtering，NCF）是深度学习推荐模型中的代表性工作之一\[2\]。NCF将传统矩阵分解中的内积操作扩展为可学习的非线性函数，通过Embedding层学习用户与物品的潜在表示，并利用MLP对交互进行非线性建模，在隐式反馈场景中取得较好的排序效果。在训练方式上，NCF常采用二元交叉熵损失（BCE）并配合负采样构建训练样本，以解决正样本稀缺与类别不平衡问题。相较于传统CF，NCF在表达能力方面更强，能够学习更复杂的偏好模式；但其缺点也较为明显：训练与推理往往需要更高的计算资源，模型解释性相对较弱，且对数据规模、采样策略、批大小等超参数较敏感。在实际系统中，NCF更常被用于精排或重排阶段，而不是直接在全物品集合上进行打分排序。](#摘-要)

2.  [[]{#_Toc230939979
    .anchor}混合推荐与召回\-\--重排框架研究现状](#摘-要)

[为同时兼顾推荐效果与系统效率，工业界与学术界逐步形成了以\"召回\-\--排序（重排）\"为核心的多阶段推荐框架\[17\]。该框架通常首先通过计算开销较低的召回模型从全量物品集合中筛选候选集，再利用表达能力更强但计算成本更高的排序模型对候选集进行精排或重排，从而在可控的计算成本下提升最终推荐质量。召回模型可以是协同过滤、内容召回、向量检索或规则策略等；排序模型则可以采用深度学习模型（如NCF、Wide&Deep、DIN等）\[18\]，并结合特征工程与在线反馈进一步优化。](#摘-要)

[混合推荐（Hybrid
Recommendation）是召回\-\--重排思想的典型体现，其融合方式包括加权融合、级联融合、特征融合与模型融合等。以\"ItemCF召回 +
NCF重排\"为例，ItemCF能够快速给出具备一定相关性的候选集合，并提供一定解释性；NCF则在候选集合范围内学习非线性交互关系，提高排序精度。该方式能够在保证在线响应的同时提升个性化程度，因此非常适合用于资源受限但希望获得更好效果的推荐系统实现。](#摘-要)

[推荐系统研究已从单一准确率指标扩展到更全面的评价体系。除Precision@K、Recall@K、NDCG@K、MAP@K和MRR@K等排序指标外，覆盖率（Coverage）、新颖性（Novelty）和推荐列表内相似度（ILS）等维度也被纳入评估框架，用于衡量推荐系统对长尾物品的挖掘能力和推荐结果的多样性。混合推荐的实际效果依赖于召回候选集质量、重排模型能力和评估协议的一致性，需要结合具体数据与场景进行系统化设计与实验验证。](#摘-要)

2.  [ []{#_Toc230939987 .anchor}协同过滤与ItemCF算法](#摘-要)

    1.  [[]{#_Toc230939988 .anchor}相似度计算与TopK近邻思想](#摘-要)

[协同过滤通过用户对物品的历史行为建立物品之间的相似关系。ItemCF的核心思想是：若两部电影被大量相同用户共同评分，则两部电影具有较高相似性。本文采用调整余弦相似度(Adjusted
Cosine
Similarity)度量电影相似性，先对评分进行用户均值归一化以消除评分尺度偏差：](#摘-要)

[在评分数据场景中，常用的相似度度量之一是余弦相似度（Cosine
Similarity）。将每个物品表示为一个用户维度的向量，其中向量元素可以是评分值、归一化评分或是否交互的0/1值。对于物品(i)与物品(j)，其余弦相似度可理解为两向量夹角的余弦值，反映二者在用户行为空间中的方向一致性。余弦相似度越大，说明两部电影在用户群体中的偏好模式越接近。](#摘-要)

  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
                                                                            [$$R_{u,i}^{\text{norm}}\  = \ R_{u,i}\  - \ \mu_{u}$$](#摘-要)                                                                          [(2-2)](#摘-要)
  --- ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ -----------------
       [$$\text{sim}(i,\ j)\  = \ \text{cos}({Col}_{i},\ {Col}_{j})\  = \ \frac{\Sigma_{u \in U\ _{ij}}^{\ }{R_{u,i}\  \cdot \ R_{u,j}}}{\left| {Col}_{i} \right|\  \times \ \left| {Col}_{j} \right|}$$](#摘-要)    [(2-1)](#摘-要)

  ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

[由于物品数量可达数万级别，完整相似矩阵的存储开销为O(N²)。工程中采用TopK近邻截断策略：对每个物品仅保留相似度最高的K个邻居，形成稀疏相似图，从而降低存储占用。在线召回阶段，系统通过批量IN查询将逐电影的N次相似查询合并为单次数据库查询，进一步提升在线检索效率。](#摘-要)

[综上，ItemCF通过\"余弦相似度 +
TopK近邻\"构建物品相似关系，能够在较低工程复杂度下实现可解释、易部署的推荐召回模型，适合作为召回\-\--重排框架中的第一阶段。](#摘-要)

3.  [ []{#_Toc230939989 .anchor}神经协同过滤NCF模型](#摘-要)

    1.  [[]{#_Toc230939990 .anchor}Embedding表示与MLP结构](#摘-要)

[神经协同过滤(NCF)将传统矩阵分解中的内积操作扩展为可学习的非线性函数\[2\]。NCF模型包含两类核心组件：(1)Embedding层，将离散用户ID与物品ID映射为稠密向量；(2)MLP交互层，将用户与物品Embedding拼接后输入多层感知机进行非线性变换，最终输出偏好得分。相较于内积，MLP能够学习更复杂的特征交互模式，在排序任务中具备更强的表达能力。](#摘-要)

4.  [ []{#_Toc230939991 .anchor}混合推荐框架（召回\-\--重排）](#摘-要)

[推荐系统通常采用\"召回-重排\"多阶段架构。召回阶段使用轻量模型(如ItemCF)从全量物品中快速筛选候选集；重排阶段使用表达能力更强的模型(如NCF)对候选集精排，在可控计算成本下提升Top-K推荐质量。本文采用级联融合方式：ItemCF负责召回，NCF负责重排，二者通过统一推荐接口的策略参数实现灵活切换。除级联融合外，常见的混合推荐融合方式还包括加权融合（对多个模型的预测分数进行加权求和）和特征融合（将不同模型的Embedding拼接后输入统一排序模型）。级联融合的优势在于召回和重排模型可独立训练与优化，召回阶段计算开销可控，适合资源受限但需要个性化排序的应用场景。](#摘-要)

5.  [ []{#_Toc230939992 .anchor}离线评价指标](#摘-要)

[离线评价（Offline
Evaluation）是在不影响真实用户体验的情况下，对推荐模型效果进行快速对比与迭代的重要手段。本文采用Top-K推荐评估范式：对每个用户生成长度为K的推荐列表，并依据用户在测试集中的真实交互行为判断推荐列表的命中情况与排序质量。为全面评估推荐系统性能，本文从准确率、排序质量以及多样性与偏置等多个维度选择评价指标^\[11,12,21\]^。](#摘-要)

1.  [[]{#_Toc230939993
    .anchor}准确率类指标（Precision@K、Recall@K、MAP@K）](#摘-要)

[（1）Precision@K（准确率）](#摘-要)

[Precision@K用于衡量推荐列表前K项中有多少比例是用户真正感兴趣的物品。对单个用户而言，可将\"真实喜欢/真实交互\"的物品集合记为(T_u)，推荐列表记为(R_u(K))，则Precision@K可理解为(\|R_u(K)cap
T_u\|/K)。该指标能够直观反映推荐列表的\"命中密度\"，适合评价用户看到的前K个结果中有多少是有效推荐。](#摘-要)

  -------------------------------------------------------------------------------------------
      [$$Precision@K\  = \ \frac{|R_{u}(K)\  \cap \ T_{u}|}{K}$$](#摘-要)   [(2-6)](#摘-要)
  --- --------------------------------------------------------------------- -----------------

  -------------------------------------------------------------------------------------------

[（2）Recall@K（召回率）](#摘-要)

[Recall@K用于衡量用户真实感兴趣物品集合中有多少比例被推荐列表覆盖。其含义可理解为(\|R_u(K)cap
T_u\|/\|T_u\|)。与Precision相比，Recall更强调\"覆盖真实兴趣\"的能力，特别适用于测试集中每个用户可能存在多个真实目标物品的情形。一般来说，Precision与Recall之间存在权衡：提高Recall往往需要更大的候选覆盖范围，可能导致Precision下降。](#摘-要)

  ----------------------------------------------------------------------------------------------
      [$$Recall@K\  = \ \frac{|R_{u}(K)\  \cap \ T_{u}|}{|T_{u}|}$$](#摘-要)   [(2-7)](#摘-要)
  --- ------------------------------------------------------------------------ -----------------

  ----------------------------------------------------------------------------------------------

[（3）MAP@K（平均准确率均值）](#摘-要)

[MAP@K用于衡量推荐列表的整体检索质量，能够同时考虑命中位置与命中数量。其思想是：当推荐列表中出现一个相关物品时，计算该位置处的Precision，并对所有相关物品求平均得到AP@K（Average
Precision@K）；再对所有用户的AP@K取平均得到MAP@K。相较于单纯的Precision与Recall，MAP对\"相关物品是否靠前出现\"更加敏感，更适合评价Top-K检索场景下的综合性能。](#摘-要)

2.  [[]{#_Toc230939994 .anchor}排序类指标（NDCG@K、MRR@K）](#摘-要)

[（1）NDCG@K（归一化折损累计增益）](#摘-要)

[NDCG@K用于衡量推荐排序质量，核心思想是对靠前位置的命中给予更高权重。具体计算为DCG@K
= Σ(i=1 to K)
(2\^(rel_i)-1)/log_2(i+1)，其中rel_i为第i位物品的相关性（1或0），再除以理想排序的IDCG@K进行归一化。NDCG取值0\~1，越接近1表示排序越接近理想状态。本文使用NDCG@K评估推荐结果中\"命中是否靠前\"，以反映模型在排序层面的优化效果。](#摘-要)

  ---------------------------------------------------------------------------------------------------------------------------------------------------------
      [$$NDCG@K\  = \ \frac{DCG@K}{IDCG@K},\ DCG@K\  = \ \Sigma_{i = 1}^{K}\frac{2^{{rel}_{i}}\  - \ 1}{\log_{2}(i\  + \ 1)}$$](#摘-要)   [(2-8)](#摘-要)
  --- ----------------------------------------------------------------------------------------------------------------------------------- -----------------

  ---------------------------------------------------------------------------------------------------------------------------------------------------------

[（2）MRR@K（平均倒数排名）](#摘-要)

[MRR@K关注推荐列表中\"第一个相关物品\"的排名位置。对单个用户而言，若第一个相关物品在推荐列表中的位置为(r)，则RR（Reciprocal
Rank）为(1/r)；若Top-K中没有相关物品则记为0。对所有用户取平均得到MRR@K。MRR适合用于测试集中每个用户仅有少量目标物品、或更关心\"是否能尽快看到一个满意结果\"的场景。与NDCG相比，MRR更突出首命中的重要性。](#摘-要)

6.  [[]{#_Toc230939995 .anchor}LightGCN与EASE模型](#摘-要)

[LightGCN（Lightweight Graph Convolution
Network）是一种轻量级图卷积推荐模型。与传统GCN不同，LightGCN去除了特征变换和非线性激活，仅保留邻域聚合操作。本文采用3层图卷积，Embedding维度为64，层输出通过均值聚合得到最终表示，使用贝叶斯个性化排序（BPR）损失进行训练。EASE（Embarrassingly
Shallow Autoencoders for Sparse
Data）是一种基于闭式解的线性推荐模型。给定用户-物品交互矩阵X，EASE通过求解B=(G+λI)\^(-1)·G得到物品-物品权重矩阵B，其中G=X\^TX为物品共现矩阵，λ=500为正则化系数，最后强制diag(B)=0以避免物品自推。EASE不需要梯度下降训练，在CPU上约10秒即可完成16K×16K矩阵的闭式求解。两个模型将在第6章作为扩展对比模型参与离线评估。](#摘-要)

        1.  [[]{#_Toc230940012 .anchor}系统模块划分](#摘-要)

[本文实现的电影推荐系统采用\"数据层\-\--服务层\-\--展示层\"分层设计，并结合离线训练与离线评估形成闭环。系统主要由以下模块组成：](#摘-要)

[（1）数据管理模块：基于MySQL实现用户、电影、评分、电影相似度以及推荐反馈等数据的持久化存储，通过SQLAlchemy
ORM完成数据访问与事务管理。](#摘-要)

[（2）离线训练与评估模块：包含ItemCF、NCF、EASE和LightGCN四种模型的训练脚本，以及统一的离线评估框架。训练阶段，ItemCF将TopK相似电影写入相似度表，其余模型将权重与映射元信息保存至backend/artifacts/目录。评估阶段，所有模型在统一的C_all=13,304候选集上进行全量排序对比，计算Precision@K、Recall@K、NDCG@K、MRR@K、Coverage等11项指标，并支持消融实验的参数扫描与结果输出。](#摘-要)

[（3）在线推荐服务模块：基于Flask应用工厂模式构建REST风格API，提供认证、电影查询、评分提交、推荐、可视化统计等接口。推荐接口支持itemcf、ncf、hybrid三种策略，可通过参数控制推荐条数与召回候选数；同时提供推荐反馈接口（/api/feedback）记录用户对推荐结果的评价数据^\[19\]^。](#摘-要)

[（4）前端展示模块：采用Jinja2模板引擎与Vue.js 3混合架构，结合Bootstrap
5暗色主题与ECharts可视化库，实现推荐结果展示、策略切换、用户画像、评分时间线、数据统计图表和离线评估对比等功能页面。](#摘-要)

[系统的数据流可分为离线与在线两部分：](#摘-要)

[（1）离线数据流](#摘-要)

[首先将MovieLens数据导入数据库，形成电影表与评分表；随后执行ItemCF训练脚本计算电影相似度并写入movie_similarity表；执行NCF训练脚本完成模型训练后生成ncf_v2.pt与ncf_v2_meta.json等模型产物；最后通过离线评估脚本计算多模型指标并写入evaluation_results.json等文件，用于Dashboard展示与结果分析。](#摘-要)

[（2）在线业务流程](#摘-要)

[用户通过注册与登录接口完成身份认证；用户可通过电影查询接口检索电影并提交评分；当用户请求推荐时，服务端根据策略参数执行对应流程：](#摘-要)

[itemcf：基于用户历史评分从相似度表召回并排序输出；](#摘-要)

[ncf：在候选集范围内用NCF对电影逐一打分并排序输出；](#摘-要)

[hybrid：先通过ItemCF召回候选集合，再用NCF对候选集合重排输出。](#摘-要)

[用户在查看推荐列表或电影详情页时可进行反馈，系统将反馈写入反馈表；用户可在前端查看个人画像、时间线与可视化统计图表，并对推荐结果提交反馈。](#摘-要)

32M数据集为基础构建推荐系统训练数据。数据导入阶段通过import_fast.py脚本完成电影信息与评分信息的快速解析与入库：电影表包含电影ID、标题、年份、类型等基础字段，以及通过TMDB
API补充的海报、导演、演员、剧情简介等元数据；评分表包含用户ID、电影ID、评分值与时间戳等字段。入库后通过数据库约束保证数据一致性，例如评分表设置(user_id,
movie_id)联合唯一约束以避免同一用户对同一电影出现重复记录。](#摘-要)

[考虑到MovieLens
32M版本数据量较大，为提高训练与调参迭代效率，系统在数据预处理阶段实施了严格的过滤策略：按min_ratings_per_movie（默认50条）过滤冷门电影，按min_ratings_per_user（默认5条）过滤不活跃用户，确保在有效数据上进行训练与评估。NCF训练中可通过user_mod参数对用户进行模采样以进一步控制训练规模。该处理方式在保持数据基本分布特征的同时，降低了离线训练与评估的时间成本。](#摘-要)

2.  [[]{#_Toc230940028 .anchor}训练/验证划分策略](#摘-要)

[本文在NCF训练中采用三层时间切分策略：对每个用户的交互记录按时间戳排序，取items\[:-5\]作为训练集，items\[-5\]作为验证集（仅用于早停决策），items\[-3:\]作为测试集（评分≥4.0的交互，最终评估使用）。该策略保证了训练(train)、验证(val)、测试(test)三部分在时间维度上严格隔离------验证集和测试集均来自用户最近的交互，且互不重叠，从设计层面消除了数据泄露风险。](#摘-要)

3.  [[]{#_Toc230940029 .anchor}负采样策略](#摘-要)

[NCF采用隐式反馈二分类建模，需要将正样本（用户已交互电影）与负样本（用户未交互电影）共同组成训练批次。由于未交互电影数量巨大，本文采用负采样策略：对训练集中采样得到的正样本对（user,
item）进行扩展，为每个正样本按一定比例随机采样负样本电影，形成标签为0的负样本集合，并与正样本合并后训练模型。负采样比例通过参数neg_ratio控制，能够在训练成本与学习效果之间进行权衡。](#摘-要)

2.  [ []{#_Toc230940030 .anchor}ItemCF召回模型实现](#摘-要)

    1.  [[]{#_Toc230940031 .anchor}相似度计算与TopK存储](#摘-要)

[ItemCF训练阶段的目标是计算电影之间的相似度并保留TopK近邻关系，以支持在线召回与相似电影查询。本文采用余弦相似度度量电影之间的相似性，并在计算前对评分进行用户均值归一化处理，以消除不同用户评分尺度差异对相似度估计的影响。工程实现中，首先从数据库中读取(user_id,
movie_id,
rating)三元组，经数据过滤和归一化后构造成\"电影×用户\"的稀疏矩阵：行表示电影，列表示用户，矩阵值为归一化后的评分。随后使用scikit-learn的NearestNeighbors模块在余弦距离空间构建最近邻索引，高效检索每部电影的相似邻居。](#摘-要)

[本文的ItemCF训练命令如下：](#摘-要)

> [python -m backend.scripts.train_itemcf \--topk 50
> \--min-ratings-per-movie 50 \--min-ratings-per-user 5
> \--normalize](#摘-要)

[其中topk=50表示对每部电影保留相似度最高的50个邻居（在实现中会额外包含自身再剔除）。训练得到的相似关系以稀疏形式写入数据库表movie_similarity，字段包括目标电影ID、相似电影ID与相似度分数。该设计避免构建全量相似矩阵，降低存储开销并提升在线查询性能。](#摘-要)

2.  [[]{#_Toc230940032 .anchor}召回生成与可解释性输出](#摘-要)

[在线推荐阶段，系统根据用户历史评分电影作为种子集合，从movie_similarity表中查询每个种子电影的相似邻居，并采用\"相似度×用户评分\"的加权累加方式计算候选电影的召回分数。候选电影按得分排序后，过滤掉用户已评分电影，输出Top-N推荐结果。](#摘-要)

[为提高推荐结果的可解释性，系统同时记录\"候选电影得分来自哪些种子电影的贡献\"，并在输出推荐列表时提供\"because\"字段，展示对该推荐贡献最大的若干部用户喜欢的电影及其贡献权重。该方式使推荐结果具备可追溯性------用户可以查看每部推荐电影具体来自哪些已评分电影的贡献。](#摘-要)

3.  [ []{#_Toc230940033 .anchor}NCF重排模型实现](#摘-要)

    1.  [[]{#_Toc230940034 .anchor}模型结构与参数设置](#摘-要)

[本文构建的NCF模型由用户Embedding层、物品Embedding层与MLP交互网络组成。用户与电影ID首先映射为维度为embedding_dim（64，ncf_v2.pt实际值）的稠密向量表示，随后将用户Embedding与电影Embedding拼接，输入三层MLP进行非线性变换（结构为\[2d→hidden_dim→hidden_dim/2→1\]，每层间使用ReLU激活函数），最终输出用户对电影的偏好得分（logit）。与传统协同过滤的内积形式相比，该结构能够刻画更复杂的非线性偏好关系，适用于候选集重排阶段。](#摘-要)

[本文在CPU上训练NCF模型（系统同时支持CUDA模式，通过\--device
cuda切换至GPU加速），训练命令如下：](#摘-要)

> [python -m backend.scripts.train_ncf_v2 \--embedding-dim 64
> \--hidden-dim 256 \--neg-ratio 4 \--epochs 20 \--batch-size 4096
> \--device cuda \--lr 1e-3](#摘-要)

[其中，embedding_dim=64为Embedding向量维度；hidden_dim=256为MLP隐藏层规模；neg_ratio=4表示每正样本采样4个负样本；epochs=20为最大训练轮数（配合早停机制，实际可能提前终止）；lr=1e-3为Adam优化器学习率；device=cuda表示默认使用GPU训练（也可通过\--device
cpu切换至CPU模式）。](#摘-要)

2.  [[]{#_Toc230940035 .anchor}训练流程与验证指标（HR/NDCG）](#摘-要)

[训练流程以隐式反馈二分类为目标：将训练集中用户交互过的电影作为正样本，通过带碰撞检测的负采样机制构造负样本（每个正样本采样neg_ratio个负样本，若采样到的负样本属于用户正样本集合则重新采样，最多重试48次），使用二元交叉熵损失函数（BCEWithLogitsLoss）优化模型参数，并采用Adam优化器进行梯度更新。为控制训练过程与防止过拟合，本文在每轮训练后于验证集上计算排序指标HR@K与NDCG@K，并引入早停机制（patience=3）：若验证NDCG在连续3轮内未提升则提前终止训练，并恢复至验证效果最好的模型参数。](#摘-要)

[在验证阶段，为避免对全物品集合逐一打分带来的巨大计算开销，本文采用\"正样本+采样负样本\"的候选集合评估方式：对每个验证正样本采样100个负样本，模型对候选集合打分并取Top-K。为进一步提升验证推理效率，本文采用分块前向（eval_forward_chunk）策略，将待评估的(user,
item)对按较大块大小分批送入模型推理，减少前向传播调用次数。若正样本在Top-K内则认为命中并用于计算HR@K；同时依据正样本排名位置计算NDCG@K，从而评估模型排序质量。](#摘-要)

5.  [ []{#_Toc230940040 .anchor}工程优化与性能提升](#摘-要)

    1.  [[]{#_Toc230940041 .anchor}数据加载与训练优化](#摘-要)

[深度学习推荐模型训练的性能瓶颈往往不完全来自模型计算本身，还可能来自数据准备、负采样、CPU到GPU的数据拷贝以及频繁的小批次前向/反向计算等环节。当训练过程出现GPU利用率较低但训练耗时较长的情况时，通常说明训练被CPU侧数据处理或数据传输所限制。针对该问题，本文在NCF训练实现中从数据准备与负采样效率两个方面进行优化，以下优化策略在CPU训练模式下同样有助于提升整体训练效率，并在GPU环境下（通过\--device
cuda切换）可进一步加速。](#摘-要)

[首先，在负采样策略方面，NCF训练需要对正样本对（user,
item）动态生成负样本。若负采样实现方式不当（例如逐样本循环采样、频繁构造Python对象或每次采样都进行大量冲突检测），会导致训练过程在CPU端消耗较多时间。本文采用批量随机采样与碰撞检测相结合的方式生成负样本：对一个批次用户向量一次性生成负样本列，并在检测到负样本与用户正样本集合冲突时仅对冲突位置进行重采样（最多重试48次），从而降低不必要的重复采样成本，提高负采样效率。](#摘-要)

[其次，在GPU训练模式下，本文通过页锁定内存（Pinned
Memory）与异步拷贝机制减少数据传输阻塞开销：将批次数据构造成张量后进行pin_memory固定，并通过non_blocking方式传输到GPU，使数据准备与GPU计算能够更好地重叠，提高整体吞吐。此外，在GPU环境下启用cuDNN的benchmark模式加速算子选择，并设置矩阵乘法精度策略以提升浮点计算性能。训练结束后，将模型权重迁移至CPU并保存，保证模型产物在不同设备环境下具备良好兼容性与可部署性。](#摘-要)

2.  [[]{#_Toc230940042 .anchor}批大小与并行策略分析](#摘-要)

[批大小（batch
size）是影响训练效率的关键因素之一。批大小过小会导致每次计算规模不足，GPU无法充分利用并行计算资源（或在CPU上导致框架调度开销占比上升）；批大小适当增大可以提升单次计算的吞吐，使计算资源利用率提高并缩短单位epoch耗时。然而，批大小过大也可能带来显存压力（GPU模式）或影响优化过程的收敛特性，需要结合模型规模与硬件条件进行权衡。](#摘-要)

[本文训练NCF模型时，为提升训练吞吐，采用较大的批大小设置（如batch_size=4096），并结合负采样比例控制单步训练样本规模。在验证评估阶段，若直接对全量候选进行逐条推理会造成大量小规模前向调用，反而降低效率。因此，本文在验证阶段采用\"分块前向\"的方式：将待评估的(user,
item)对展开后按较大块大小（由eval_forward_chunk参数控制）分段送入模型进行推理，减少前向传播调用次数并提升推理吞吐，从而在保证评估一致性的同时降低验证耗时。](#摘-要)

[除批大小外，本文还通过早停机制减少无效训练轮次：当验证NDCG在连续若干轮未提升时提前停止训练，并恢复最佳模型参数。这一策略在保证效果的同时降低总体训练时间，使离线训练更适合在有限时间窗口内完成多组参数对比与消融实验。](#摘-要)

[通过负采样批量化、碰撞检测、验证推理分块和早停等策略，NCF单轮训练时间控制在可接受范围内，验证集NDCG@10达到0.8148（采样评估协议：每正样本配100负样本计算排序指标；该值反映模型在候选集重排场景下的排序能力，与第6章全量排序评估的NDCG指标不具备直接可比性）。](#摘-要)

3.  [[]{#_Toc230940046 .anchor}推荐API核心实现](#摘-要)

[推荐API（GET
/api/recommendations）是系统的核心接口，接受n（推荐数量，默认10，最大50）、strategy（推荐策略，可选itemcf/ncf/hybrid）、recall_k（Hybrid召回数量，默认100，最大500）三个参数。对于冷启动用户（未登录或评分记录为空），系统调用popular_movies()逻辑返回高评分热门电影兜底：查询平均评分较高且评分数量≥50的电影，按评分和热度排序。ItemCF策略的核心在于_itemcf_recall()函数：该函数通过单次IN子句查询批量获取所有已评分电影的相似电影列表（避免经典N+1查询问题），按movie_id分组并每组取Top-50，在分数累加时过滤已评分的电影避免推荐重复内容，最后按贡献分数降序排列取Top-N。\_format_recommendations()函数负责将(item_id,
score)列表格式化为包含电影详情、推荐分数和推荐理由（because字段，展示贡献最大的3部种子电影）的JSON响应。NCF策略首先检查NCFEngine状态：若is_loading()返回True则返回503状态码提示用户稍后重试；若is_ready()返回False则尝试加载模型；若模型不可用或用户不在训练映射中则自动降级为ItemCF策略。Hybrid策略先以recall_k参数执行ItemCF召回获取候选集，若NCF可用则将候选集送入NCF进行重新评分排序，否则直接截取ItemCF召回结果输出。](#摘-要)

4.  [[]{#_Toc230940047 .anchor}推荐解释机制](#摘-要)

[推荐解释通过/api/recommendations/why/\<movie_id\>端点实现。该端点接收被推荐电影ID，查询当前用户所有已评分电影中与被推荐电影存在相似度关系的记录。对每部贡献来源电影计算贡献权重（相似度分数×用户原评分），按权重降序排列后返回Top-3作为推荐理由。返回的because字段包含{movie_id,
title,
weight}三元组，前端据此展示\"因为你喜欢《X》，所以推荐《Y》\"的解释信息。这种可解释推荐机制是ItemCF算法的天然优势------相似度矩阵提供了透明的\"物品A与物品B相似\"关系，进而可以回溯推荐结果的来源。在Hybrid策略中，虽然排序阶段由NCF完成，但推荐理由仍沿用ItemCF阶段的相似度贡献信息，实现了\"深度学习排序+传统方法解释\"的互补。](#摘-要)

5.  [[]{#_Toc230940048 .anchor}用户画像服务实现](#摘-要)

[用户画像计算由ProfileService服务类实现，compute_user_profile()方法整合了12个维度的特征计算：1）偏好类型计算------遍历用户评分和收藏记录，对每部电影的genres字段拆分后进行评分加权统计，归一化后过滤分数低于0.3的类型，保留Top类型偏好；2）偏好年代计算------将电影年份映射为年代标签（如1990s），以相同评分加权方式统计年代偏好并归一化过滤；3）偏好演员计算------从movies表的actors字段（JSON格式存储）中提取演员信息进行评分加权统计，取前10位；4）偏好导演计算------从director字段统计评分加权偏好，取前10位；5）评分行为分析------计算平均评分水平、评分方差（反映评分一致性）和评分熵（反映评分散度，使用香农熵公式）；6）观影统计------累计已评分和已收藏电影的runtime字段获取总观影时长，计算类型多样性指数和年代多样性指数（均基于香农熵）；7）用户分层------根据总操作次数（评分+收藏+评论）将用户分为casual（\<10次）、regular（10-49次）、enthusiast（≥50次），活跃度分为low（\<20次）、medium（20-99次）、high（≥100次）；8）个性化洞察------基于画像数据自动生成最多5条观影洞察描述（如\"您最喜欢Drama类型的电影\"、\"您的观影类型比较丰富\"等），通过get_user_insights()方法返回给前端展示。](#摘-要)

2.  [ []{#_Toc230940060 .anchor}对比方法与评价方案](#摘-要)

    1.  [[]{#_Toc230940061 .anchor}对比方法（Baseline）设置](#摘-要)

[本文在统一协议下对以下八个方法进行离线对比（含两个统计基线Random/Popularity、一个理论上界Oracle、三种系统在线推荐策略ItemCF/NCF/Hybrid，以及EASE、LightGCN两个外部对比模型；Oracle不参与模型排名）：](#摘-要)

[（1）Random：随机推荐基线。对每个用户从候选集C_all中随机抽取10部电影，用于验证评估协议的下界。若任何模型指标低于Random，则表明该模型存在严重缺陷。](#摘-要)

[（2）Popularity：全局热门推荐基线。按电影在训练集中被评分的次数降序排列，取Top-10作为推荐结果。该基线不利用用户个性化信息，代表了最简单的非个性化推荐策略。](#摘-要)

[（3）ItemCF：基于物品的协同过滤，本系统的默认召回模型。采用余弦相似度计算电影间相似度，对评分进行用户均值归一化以消除评分尺度差异，保留TopK=50个最相似邻居。ItemCF的推荐结果可附带解释性信息（\"因为你喜欢X\"），增强用户对推荐的理解。](#摘-要)

[（4）NCF（Neural Collaborative
Filtering）：神经协同过滤模型，采用MLP（Multi-Layer
Perceptron）架构。模型包含用户和物品的Embedding层（维度64），将两个Embedding拼接后经三层MLP（256→128→1）输出预测分数，使用BCEWithLogitsLoss作为损失函数进行二分类训练。NCF在本系统中作为重排模型使用。](#摘-要)

[（5）Hybrid：ItemCF召回+NCF重排的级联策略。首先由ItemCF根据用户历史评分从相似度矩阵中召回候选电影集合（默认recall_k=200），然后将候选集送入NCF模型逐一打分，按分数降序输出Top-10。Hybrid结合了ItemCF的高效召回能力和NCF的非线性排序能力。](#摘-要)

[（6）EASE（Embarrassingly Shallow
Autoencoder）：基于物品-物品共现矩阵的闭式最小二乘模型。通过求解（G+λI）⁻¹的闭式解直接得到物品相似度矩阵B（对角线置零），无需迭代训练。正则化系数λ=500用于控制过拟合。EASE的主要优势在于训练速度快（闭式解，约8秒）、超参数少（仅λ），且对长尾物品有较好的覆盖。](#摘-要)

[（7）LightGCN：轻量图卷积协同过滤模型。在用户-物品二分图上进行3层图卷积传播，每层聚合邻居节点的Embedding信息，最终取各层Embedding的均值作为用户/物品表示，通过内积计算推荐分数。采用BPR（Bayesian
Personalized Ranking）损失进行优化，Embedding维度64。](#摘-要)

[（8）Oracle：理论上界。直接向用户推荐其测试集中的正样本物品（评分≥4.0的交互），用于验证测试集构造的正确性和评估协议的上界。Oracle不参与模型排名，仅作为验证性指标。若Oracle的Recall@10未达到1.0，则说明测试集构造或评估逻辑存在错误。](#摘-要)

2.  [[]{#_Toc230940062 .anchor}评价指标与参数设置](#摘-要)

[评估采用三层时间切分策略：对每个用户按评分时间排序后，最后第5条作为验证集（仅NCF训练使用），最后3条评分≥4.0的交互作为测试集，其余作为训练集。评估时所有模型在统一的候选集C_all上进行全量排序（非采样），C_all为ItemCF相似度矩阵与NCF物品映射的交集，共13,304部电影。测试用户10,000名（seed=42），每个用户至少16条交互。Top-K设置为K=10，使用以下指标：Precision@K、Recall@K、MAP@K、NDCG@K、MRR@K，并补充Coverage、ILS（推荐列表内相似度）与Novelty分析多样性与偏置。](#摘-要)

3.  [ []{#_Toc230940063 .anchor}实验结果与分析](#摘-要)

    1.  [[]{#_Toc230940064 .anchor}多模型离线指标对比](#摘-要)

[在C_all=13K统一候选池的全量排序协议下，ItemCF在排序精度上全面领先（R@10=0.0772，NDCG@10=0.0490），验证了传统协同过滤方法在该数据集上的有效性。EASE（R@10=0.0757，NDCG@10=0.0449）紧随其后。两种深度学习模型NCF（R@10=0.0664）和LightGCN（R@10=0.0533）均未超越传统方法，Hybrid（R@10=0.0689）虽相较纯NCF有约3.9%的提升，但仍受限于ItemCF召回阶段的候选覆盖。所有模型基于完全相同的候选集C_all进行评估，候选池大小一致保证了指标的可比性。](#摘-要)

[EASE以闭式解实现了精度与覆盖的最佳平衡：P@10仅比ItemCF低7.0%，但Coverage达到ItemCF的6.4倍（0.6580
vs 0.1024），意味着EASE能够推荐到65.8%的候选电影，将长尾物品的Tail
Coverage从0.020提升至0.128（为ItemCF的6.4倍）。这一优势源于EASE的闭式最小二乘目标直接对物品-物品共现矩阵进行稠密建模，避免了ItemCF中TopK截断导致的信息损失。在数据集规模较大时，EASE的O(n³)矩阵求逆复杂度是其主要瓶颈，但对于13K候选集的场景仍可在数秒内完成训练。](#摘-要)

[NCF和LightGCN两种深度模型在本次评估中均未超越传统方法。这一结果与部分文献中深度学习模型在小规模数据集上优势更大的结论有所不同，本文推测以下因素可能对此产生影响（未经控制变量实验验证）：（1）MovieLens
32M的评分密度较低（约0.14%），深度模型对稀疏交互的泛化能力受到限制；（2）评估采用全量排序协议（C_all=13K），增大了Top-K推荐的难度；（3）训练过程中GPU未启用，NCF和LightGCN的超参数调优可能不够充分。上述推测的确切原因有待进一步研究确认。Hybrid级联架构相较纯NCF在R@10上实现了3.9%的相对提升，表明NCF重排能够优化ItemCF召回的候选集排序，验证了召回-重排架构对候选集排序的优化潜力。但Hybrid的NDCG@10（0.0421）低于纯ItemCF（0.0490），说明当前混合策略的整体效果受限于ItemCF召回阶段的候选质量------召回阶段遗漏的相关物品无法在重排阶段恢复。](#摘-要)

[Random基线指标接近于零（P@10=0.00009），Oracle达到完美召回（R@10=1.0，NDCG@10=1.0），验证了评估协议构造的正确性。Popularity基线作为最简单的非个性化方法，P@10为0.01151，低于所有推荐模型但高于Random，表明全局热门推荐具有一定的实用价值但忽略了个体偏好差异。后续的消融实验（见6.4节）将进一步量化Hybrid召回候选数recall_k和ItemCF近邻截断per_seed_limit对推荐效果的影响。](#摘-要)

4.  [[]{#_Toc230940067 .anchor}统计显著性检验](#摘-要)

[为验证上述指标差异是否具有统计意义上的显著性，本文采用Wilcoxon
Signed-Rank检验对模型间Precision@10和NDCG@10的逐用户差异进行成对比较，并使用Bonferroni-Holm方法对p值进行多重比较校正。该检验为非参数方法，不依赖指标分布的正态性假设，适用于推荐模型对比中逐用户指标差异的显著性判断。](#摘-要)

[检验结果显示，所有模型对之间的Precision@10和NDCG@10差异均达到统计显著水平（p\<0.01）。其中，EASE与ItemCF在NDCG@10上的差异显著（p=0.00846），但效应量较小（Cohen's
d=0.029）；ItemCF与LightGCN的NDCG@10差异高度显著（p=1.2×10⁻²³），效应量中等（d=0.106）。尽管所有成对比较均通过显著性检验，但各模型间的实际效应量均处于较小范围（Cohen's
d
0.03-0.12），表明模型间精度差异虽具有统计意义，但实际幅度有限。这一结果与Henderson和Ferrari在推荐系统评估中关于统计显著性与实际显著性之间差异的讨论一致。](#摘-要)

5.  [[]{#_Toc230940068 .anchor}结果讨论](#摘-要)

[综合以上实验结果，本文得出以下主要发现。第一，传统协同过滤方法在MovieLens
32M数据集上的排序精度优于深度学习模型。ItemCF以余弦相似度和用户均值归一化实现了最优的Precision@10和NDCG@10，EASE以闭式最小二乘解紧随其后。这一现象与近年研究中深度学习模型在稠密、大规模交互数据上优势更大的结论有所不同，说明在评分稀疏度较高的场景中，精心设计的传统方法仍具有很强的竞争力。两种方法均在CPU上完成训练和推理，训练时间分别为ItemCF约5分钟、EASE约8秒（闭式解），远低于NCF（约20分钟/10轮）和LightGCN（约40分钟/50轮），实际部署成本更低。](#摘-要)

[第二，EASE以闭式解实现了精度与覆盖的最佳综合表现。在P@10仅比最优值低7.0%的前提下，EASE的Coverage达到ItemCF的6.4倍、Novelty达到2.5倍，明显提升了长尾物品的覆盖。对于注重推荐多样性和内容发现的视频/音乐平台而言，EASE可以在不大的精度代价下提供更丰富的推荐结果。其闭式解特性使得超参数调优极为简单（仅需调节正则化系数λ），避免了深度学习模型中学习率、网络结构、训练轮数等多维超参数的调优负担。](#摘-要)

[第三，Hybrid级联架构的召回-重排管道被验证为有效方向。Hybrid相较纯NCF在R@10上提升了3.9%，但整体仍受限于ItemCF召回阶段的候选质量。消融实验（见6.4节）进一步表明，减小Hybrid召回候选数（recall_k=50）和ItemCF每种子近邻数（per_seed_limit=10）能够同时提升排序精度和覆盖率，说明在协同过滤召回阶段仅保留最可靠的TopK相似信号即可有效过滤弱相似噪声。这一发现为推荐系统的级联架构设计提供了参数选择依据：召回阶段应追求高质量小候选集而非大规模高噪声候选集。](#摘-要)

[本研究的局限性主要包括以下方面。在模型层面，NCF和LightGCN在CPU环境下训练，超参数搜索范围有限，GPU加速和大规模超参数调优可能进一步缩小其与传统方法的差距。在评估层面，离线指标与实际用户满意度之间存在差距，A/B测试和在线评估是下一步工作的方向。在数据集层面，MovieLens
32M作为学术公开数据集，其评分分布和用户行为模式与实际商业场景存在差异，模型的跨域泛化能力有待验证。](#摘-要)

4.  [[]{#_Toc230940073 .anchor}本节小结](#摘-要)

[两项消融实验共同指向一个规律：在协同过滤召回阶段，仅保留最可靠的Top-K相似信号能够有效过滤弱相似噪声，同时提升排序质量和覆盖率。Hybrid的recall_k取50时，召回-重排架构首次产生正向增益；ItemCF的per_seed_limit取10时，精度和覆盖率均处于最优水平。当前默认设置（per_seed_limit=50，recall_k=200）并非最优，本文推荐per_seed_limit=10、recall_k=50作为部署配置。该发现与直觉中\"更多邻居提供更多信息\"的预期不符，为协同过滤召回阶段的超参数选择提供了实验依据。](#摘-要)

7.  [ []{#_Toc230940078 .anchor}总结与展望](#摘-要)

    1.  [ []{#_Toc230940079 .anchor}工作总结](#摘-要)

[本文设计并实现了多策略电影推荐系统CineMatch，覆盖数据管理、离线训练、离线评估、在线服务与前端展示五个环节。数据层基于MovieLens
32M数据集（3,200万条评分，覆盖27万用户与8.7万部电影），通过TMDB
API补充电影海报、导演、演员和剧情简介等元数据，使用MySQL进行持久化存储。后端基于Flask应用工厂模式构建REST风格API，前端采用Jinja2模板引擎与Vue.js
3混合架构，结合Bootstrap
5暗色主题与ECharts可视化库，实现了推荐交互、用户画像、数据看板和管理后台等完整功能页面。](#摘-要)

[算法层面，系统实现了四种推荐模型：ItemCF（余弦相似度+用户均值归一化，TopK=50稀疏存储）作为主召回模型，NCF（MLP架构，64维Embedding+256维隐藏层，BCE损失+负采样训练）作为重排模型，以及EASE（闭式最小二乘，λ=500）和LightGCN（3层图卷积，BPR损失）两个外部对比模型。Hybrid管道以ItemCF为召回阶段、NCF为重排阶段实现级联推荐，并通过三级回退策略（NCF→ItemCF→Popular）保障推荐服务在NCF模型未就绪时的可用性。系统同时实现了用户画像分析（12维特征）、行为追踪（异步线程池）、收藏管理、评论与点赞、推荐反馈采集（like/dislike+context）等功能模块。](#摘-要)

[实验方面，本文建立了基于三层时间切分的离线评估协议，在统一候选集C_all=13,304上对8个模型（含Random/Popularity统计基线和Oracle理论上界）进行全量排序对比，计算Precision@K、Recall@K、NDCG@K、MRR@K、Coverage、ILS、Novelty等11项指标。主要实验发现包括：（1）ItemCF在排序精度上表现最优（R@10=0.0772，NDCG@10=0.0490），NCF和LightGCN两种深度学习方法在此大规模稀疏场景中未超越传统协同过滤方法；（2）EASE以闭式解实现了精度与覆盖的最佳平衡（Coverage=0.658，为ItemCF的6.4倍，P@10仅低7.0%）；（3）Hybrid级联架构相较纯NCF在R@10上提升了3.9%，验证了召回-重排对候选集排序的优化潜力，但其整体效果仍受限于ItemCF召回阶段的候选质量；（4）消融实验发现per_seed_limit=10和recall_k=50为最优参数取值，均优于当前默认配置。](#摘-要)

[工程实现方面，系统采用模块化架构，将数据导入、模型训练、离线评估和在线服务解耦为独立组件，支持灵活的策略配置与模型扩展。系统在Windows
11单机开发环境下可完整运行全部功能模块，NCF模型通过异步加载与单例模式管理内存，推荐接口的平均响应时间在ItemCF策略下响应迅速，可满足本地交互使用需求。所有评估结果和消融实验数据以JSON格式持久化，通过Dashboard看板实现可视化展示，可作为推荐算法离线对比研究的实验基线。](#摘-要)

2.  [ []{#_Toc230940080 .anchor}不足与展望](#摘-要)

[本文在以下方面存在局限，对应的改进方向如下：](#摘-要)

[（1）NCF排序效果方面，当前模型（64维Embedding、256维隐藏层、4倍负采样）的全量排序NDCG@10为0.0409，与验证集NDCG@10（0.8146）之间存在约17倍差距。这一差距的根源在于训练目标（BCE+负采样）与评估目标（全量排序）不匹配。将损失函数替换为Pairwise排序损失（如BPR）或采用全量softmax训练，是缩小这一差距最直接的方向。](#摘-要)

[（2）冷启动问题仍需解决。本系统目前主要依赖评分交互数据，对新用户和新电影的推荐效果有限。TMDB已补充的电影元数据（类型、年份、简介、演员、导演）为内容感知推荐提供了基础------基于这些特征构建内容召回模型，或结合知识图谱进行物品表示学习，都有望改善冷启动场景下的推荐质量。用户画像系统与反馈信号也可用于新用户的偏好初始化。](#摘-要)

[（3）混合推荐框架的召回和排序阶段均有扩展空间。召回侧，向量检索（如基于Embedding的ANN）和矩阵分解模型（如BPR-MF）可作为ItemCF的补充或替代方案，形成多路召回架构。排序侧，引入多任务学习或特征交叉模型以更充分地利用物品特征和上下文信息，有望进一步提升重排质量。](#摘-要)

[（4）从离线评估走向在线验证。系统已具备推荐反馈采集和行为追踪能力，在此基础上搭建在线指标监控（如点赞率、点击率），将离线结论与实际用户行为对照，是将离线评估结论与实际用户行为对照的直接方式。](#摘-要)

[（5）工程层面，当前训练服务和Web服务耦合在同一进程中，将其拆分为独立服务有助于提升稳定性和可维护性。数据加载和模型推理的优化（如CSV/Pickle缓存、CUDA加速、推理分块）数据缓存和推理优化已在当前系统中使用。](#摘-要)

数据库表结构（核心表）A.1 用户表 users](#摘-要)

[id：int，主键](#摘-要)

[username：varchar(64)，唯一，索引](#摘-要)

[password_hash：varchar(256)](#摘-要)

[created_at：datetime](#摘-要)

[A.2 电影表 movies](#摘-要)

[id：int，主键](#摘-要)

[title：varchar(255)，索引](#摘-要)

[year：int，可为空，索引](#摘-要)

[genres：varchar(255)，可为空](#摘-要)

[A.3 评分表 ratings](#摘-要)

[id：int，主键](#摘-要)

[user_id：int，外键→users.id，索引](#摘-要)

[movie_id：int，外键→movies.id，索引](#摘-要)

[rating：float](#摘-要)

[timestamp：datetime，可为空](#摘-要)

[约束：(user_id, movie_id)联合唯一约束，避免重复评分](#摘-要)

[A.4 电影相似度表 movie_similarity](#摘-要)

[id：int，主键](#摘-要)

[movie_id：int，外键→movies.id，索引](#摘-要)

[similar_movie_id：int，外键→movies.id，索引](#摘-要)

[score：float（相似度分数）](#摘-要)

[约束：(movie_id, similar_movie_id)联合唯一约束](#摘-要)

[A.5 推荐反馈表 recommendation_feedback](#摘-要)

[id：int，主键](#摘-要)

[user_id：int，外键→users.id，索引](#摘-要)

[movie_id：int，外键→movies.id，索引](#摘-要)

[feedback：varchar(16)（like/dislike）](#摘-要)

[context：varchar(64)（反馈场景）](#摘-要)

[created_at：datetime，索引](#摘-要)

[约束：(user_id, movie_id, context)联合唯一约束](#摘-要)
