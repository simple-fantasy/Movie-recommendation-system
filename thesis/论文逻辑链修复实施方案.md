# 第一部分：逻辑风险总览

## 当前最大逻辑风险

**"标题承诺了融合优势，但实验数据反证了融合方案不如纯传统方法。"**

这是唯一可能导致答辩失败的问题。答辩老师只需要看三样东西:
1. 论文标题 → "融合协同过滤与深度学习的电影推荐系统"
2. 实验结论表6-1 → ItemCF NDCG@10=0.0490, Hybrid NDCG@10=0.0421
3. 问一句: "你的融合方案比纯协同过滤好在哪？"

论文目前没有准备好回答这个问题。

## 最可能导致答辩失败的问题

| 排名 | 答辩老师可能问的问题 | 论文当前能回答吗 |
|------|-------------------|---------------|
| 1 | "Hybrid比纯ItemCF好在哪？" | ❌ 没有——实际上更差 |
| 2 | "你的深度学习模型为什么不如传统方法？" | ⚠️ 列了3个"可能原因"，但无验证 |
| 3 | "论文到底实现了几个推荐策略？" | ⚠️ 不同章节说法不同 |
| 4 | "你说'验证了有效性'——验证了什么？" | ❌ 没有明确定义"有效性" |
| 5 | "EASE比ItemCF Coverage高6.4x，为什么不用EASE做召回？" | ❌ 没有讨论 |

## 最危险章节

| 章节 | 危险度 | 原因 |
|------|--------|------|
| **第6章 实验结果与分析** | 🔴 高 | 结果解读回避核心矛盾 |
| **第1章 绪论** | 🔴 高 | 研究意义和目标与实验结论不对齐 |
| **第7章 总结** | 🟡 中 | 过度解读、夸大结论、AI结语 |
| **第3章 需求分析** | 🟡 中 | EASE/LightGCN错误定位为系统需求 |

## 最危险实验

| 实验主张 | 危险 | 原因 |
|---------|------|------|
| "Hybrid验证了召回-重排管道的有效性" | 🔴 | 如果"有效"指优于ItemCF → 数据不支持 |
| "深度模型对稀疏交互的泛化能力受限" | 🟡 | 推测而非验证，答辩可能被追问 |
| "显著改善长尾物品曝光" (EASE) | 🟡 | "显著"无统计检验支撑 |

# 第二部分：修复原则

## 核心原则

1. **先修主链，后修细节。** 标题-摘要-结论这条主链必须首先对齐，然后才修章节内部一致性
2. **先修目标，再修实验。** 明确论文到底想证明什么，然后调整实验解读匹配目标
3. **先修证据，再修结论。** 确保每个结论都有数据支撑，无数据的降级为推测
4. **先修一致性，再修表达。** 术语统一、数字对齐优先于措辞润色
5. **诚实优于美观。** 报告"深度方法在此场景不如传统方法"是可以的——只要诚实
6. **一次只修一个逻辑问题。** 每步修改后检查逻辑链是否仍然完整
7. **可回滚。** 每步前备份docx

## 不处理的内容

- 格式排版（字体、字号、行距、页码）
- 图表美化（颜色、布局、分辨率）
- 参考文献格式
- 第8章系统使用指南（单独评估是否保留）
- 图表编号一致性

| | 选项A: 诚实路线 | 选项B: 调整实验解读 |

| **叙事** | "在MovieLens 32M大规模稀疏场景中，传统协同过滤方法在排序精度上仍优于深度学习方法；混合推荐策略的召回-重排架构对提升深度模型排序有效，但整体效果受限于召回阶段质量" | 维持"融合CF+DL"的叙事框架，将Hybrid>NCF的3.9%作为核心证据，弱化Hybrid<ItemCF |

### Step 16: 全文AI措辞降级

**目标**: 降低绪论和结论中明显的AI写作痕迹

**操作**: 搜索并处理以下AI特征词汇（全文）:

| AI特征 | 处理方式 |
|--------|---------|
| "不仅...而且..." | 拆为两句 |
| "因此...从而...进而" | 最多保留一层因果 |
| "值得注意的是" | 删除 |
| "综上所述" | 替换为更自然的过渡 |
| "进一步丰富了" | 删除或具体化 |
| "显著地" | 替换为数字 |
| "具有良好的/较强的" | 替换为中性描述或删除 |
| 工整的三段式/五段式排比 | 打破数字对称 |

**验证**: 随机抽取绪论和结论各3段，人工判断AI痕迹是否明显降低
