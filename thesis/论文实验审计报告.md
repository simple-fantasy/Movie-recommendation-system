## P0-CRITICAL：阻断性缺陷

### [P0-1] NCF模型架构定性错误：论文称"GMF"，代码实现为MLP

**论文主张**（出现至少3处）：
- 第1章（[27]行）: "NCF（GMF架构）作为重排模型"
- 第6章（[358]行）: "NCF…采用GMF（Generalized Matrix Factorization）架构"
- 第7章（[450]行）: "NCF（GMF架构，32维Embedding+128维隐藏层）"

**代码证据**：
- `backend/app/ncf_engine.py:61-96` — NCF类定义
- `backend/scripts/train_ncf_v2.py:30-47` — 训练用NCF类定义
- 两处实现一致：`user_emb` + `item_emb` → **拼接(concatenate)** → 3层MLP → 输出

```python
# ncf_engine.py:95
x = torch.cat([u, i], dim=-1)  # 拼接，非逐元素乘积
return self.mlp(x).squeeze(-1)
```

**为什么这是错的**：He et al. (2017) 的原始NCF论文定义了三种架构：
- **GMF**: 逐元素乘积(element-wise product) `u ⊙ i` → 线性层
- **MLP**: 拼接(concatenate) → 多层MLP
- **NeuMF**: GMF + MLP 融合

本项目代码实际实现的是 **MLP variant**，而非GMF。`ncf_engine.py` 的 docstring 自己写了"GMF架构"但紧接着描述"拼接后通过3层MLP"——docstring本身自相矛盾。

**影响**: 论文对核心模型架构的定性描述完全错误。审稿人或答辩老师若注意到此问题，会质疑作者是否理解自己实现的模型。

**修复建议**: 将所有"GMF架构"改为"MLP架构"，并确认文献[4](He et al. 2017)中的引用是否对应正确架构。

### [P0-3] 验证集NDCG@10存在两个不可调和的值

**论文主张**：
- 第5章 [317]行: "验证集NDCG@10达到**0.8148**（采样评估协议：每正样本配100负样本）"
- 第7章 [455]行: "全量排序NDCG@10为0.0409，与验证集NDCG@10（**0.6954**）之间存在约17倍差距"

**两个值的差**: |0.8148 - 0.6954| = 0.1194 (约17%相对差异)

**代码证据**：
- `backend/artifacts/ncf_v2_meta.json`: **不包含任何训练日志或验证指标记录**
  - `best_val_ndcg`: null
  - `best_val_hr`: null
  - 无 train_log / history 字段
- `train_ncf_v2.py` 中搜索 `val_ndcg`, `best_val`, `val_hr`, `hit_rate` 均无匹配——说明训练脚本**未将验证指标写入meta.json**

**这意味着**: 0.8148 和 0.6954 **两个值均无法从代码产物中验证**。论文引用了两个不一致的验证指标，且均无证据支撑。

**影响**: 这是最严重的可信度问题。验证指标是判断模型是否过拟合的关键证据，论文提供了两个矛盾的值，且都无法验证。

**修复建议**: (1) 确定实际的最佳验证NDCG@10值；(2) 在训练脚本中增加写入验证指标到meta.json的逻辑；(3) 确保全文引用唯一正确的值。

### [P0-4] 用户分层分析使用了与评估协议不兼容的桶定义

**论文主张**（第6章 [367]行）:
> "Warm用户（**6-20条**交互记录，481人）和Hot用户（20条以上交互记录，9,519人）。由于评估协议要求每用户至少16条交互，测试集中不存在Cold用户"

**代码证据**：
- `backend/evaluation/config.py:27`: `min_user_interactions: int = 16`
- `backend/evaluation/splitter.py:8`: `if len(items) < config.min_user_interactions: continue`
- `backend/artifacts/evaluation_results.json:10`: `"min_user_interactions": 16`

**矛盾**: 若每用户至少16条交互，则Warm桶的"6-20条"定义中，6-15条区间的用户**不可能存在于测试集中**。实际Warm桶应为"16-20条"。

**影响**: 表6-3的用户分层数据来源可疑——它可能来自旧版评估脚本的结果，而非当前统一协议下的评估。

**修复建议**: 使用与评估协议(min_user_interactions=16)一致的桶定义重新进行分层分析，或明确标注分层数据来自哪个评估脚本。

## P1-HIGH：显著削弱可信度

### [P1-1] 在线推理模型(ncf.pt)与离线评估模型(ncf_v2.pt)是不同的文件

**代码证据**：

| 场景 | 加载路径 | 文件大小 | 日期 |
|------|---------|---------|------|
| 在线推理 | `backend/artifacts/ncf.pt` | 36MB | May 21 |
| 离线评估 | `backend/artifacts/ncf_v2.pt` | 62MB | May 25 |

- `backend/app/ncf_engine.py:190`: `ckpt_path = artifacts_dir / "ncf.pt"`
- `backend/evaluation/config.py:20`: `ncf_model_path: str = "backend/artifacts/ncf_v2.pt"`

**论文主张**（[296]行）: "系统将模型权重保存到backend/artifacts/ncf_v2.pt…在线推理阶段通过NCF推理引擎加载模型"

**修复建议**: (1) 更新ncf_engine.py加载ncf_v2.pt，或 (2) 创建ncf_v2.pt→ncf.pt的符号链接/复制，并明确记录；(3) 在论文中说明两个模型的对应关系。

## 实验泄露风险评估

### 三层时间切分协议检查 ✓

`splitter.py` 的三层切分逻辑:
```
train = items[:-5]
val   = items[-5]    (单条，仅NCF训练早停用)
test  = items[-3:]   (评分≥4.0的交互)
```

**结论**: 时间隔离正确。训练集(train)不包含验证集(val)和测试集(test)的任何交互；验证集和测试集互不重叠。**无时间泄露风险**。

### ItemCF相似度计算检查 ✓

`run_evaluation.py:65-70`:
```python
train_df = _build_train_df(train)  # 仅使用训练集数据
sims = compute_item_similarity(train_df, ...)  # 从训练集计算相似度
```

**结论**: ItemCF相似度仅从训练集计算，未使用验证集或测试集数据。**无数据泄露**。

### 负采样碰撞检测检查 ✓

`train_ncf_v2.py:85-96`: 负采样时检测与用户正样本集合的碰撞，最多重试48次。**采样正确**。

### 候选集过滤检查 ✓

`engine.py:52-74`: `_validate_test_items()` 确保test items在C_all中，将不在C_all中的测试项排除并移除无有效测试项的用户。同时标记"低信号用户"（训练集中所有评分均低于like_threshold）。**评估协议保守**。

**审计结论**: 论文在评估协议设计（三层时间切分、C_all公平候选集、Oracle/Random基线验证）方面**设计良好**，主要评估数据（ItemCF/EASE/NCF/Hybrid的Precision/Recall/NDCG值）与代码产物一致。但存在**4个阻断性缺陷**：NCF架构定性错误(GMF vs MLP)、模型维度全文不一致(32/128 vs 64/256)、验证NDCG值自相矛盾(0.8148 vs 0.6954)、用户分层分析使用不兼容的桶定义。这些缺陷不涉及实验数据造假（实际数据与evaluation_results.json一致），但严重影响论文的**学术准确性**和**可复现性**。修复P0级问题后，论文的实验章节可以支撑答辩。
