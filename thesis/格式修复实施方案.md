# 总体依赖关系图

```
Phase 0 (备份)
  └→ Phase 1 (页面/节结构)  ←── 所有后续阶段的物理基础
       └→ Phase 2 (标题/目录)  ←── 文档逻辑结构，后续样式依附于标题识别
            └→ Phase 3 (正文样式)  ←── 大量段落格式化，影响图表位置
                 ├→ Phase 4 (图表/题注)  ←── 浮动对象，依赖正文稳定
                 ├→ Phase 5 (公式体系)  ←── 与Phase 4并行，互不依赖
                 └→ Phase 6 (参考文献/引用)  ←── 依赖正文稳定
                      └→ Phase 7 (AI痕迹/语言)  ←── 纯文本修改，需正文稳定
                           └→ Phase 8 (最终质量门)  ←── 全部修复后的全域检查
```

**核心依赖逻辑：**

| 为什么必须先做 A 再做 B | 原理 |
|---|---|
| 节结构 → 标题体系 | 分节符决定页码起点和页眉页脚模式。如果不先固化节结构，后续标题分页和目录页码都会在节调整后漂移 |
| 标题体系 → 正文样式 | 正文样式需要批量应用到"所有非标题段落"。如果不先标记标题，就无法安全地批量选择正文段落 |
| 标题体系 → 目录生成 | 目录依赖标题的大纲级别。在标题样式修复前生成的目录必然缺少条目 |
| 正文样式 → 图表 | 图表嵌入在正文段落中。正文行距、字体、缩进的改变会导致图表锚点位置漂移。正文稳定后才能校准图表 |
| 正文样式 → 公式 | 公式使用表格布局嵌入正文。正文行距改变会影响公式行高 |
| 正文稳定 → 参考文献 | 引用标记嵌入正文。正文段落的增删会改变引用编号顺序 |
| 格式修复 → AI痕迹修复 | AI痕迹修复涉及增删文字，可能改变段落数量和页码。必须在格式稳定后进行 |

# Phase 1：页面与节结构修复

## 为什么 Phase 1 必须在 Phase 2 之前

当前文档有 5 个 Section：
- Section 0：封面（titlePg=true）
- Section 1-3：摘要/目录区域（页码格式为罗马数字 I/II，起始值=1）
- Section 4：正文区域（页码格式为阿拉伯数字，起始值=1）

如果先改标题再调分节符，会导致：
1. 标题位置在分节符调整后发生页偏移
2. 目录页码全部作废
3. 页眉页脚模式可能错乱

因此必须先固化节结构，确保物理页面边界稳定。

## 修复目标

1. 为每章创建独立的分页边界（每章从新页开始）
2. 确保页码系统正确：封面无页码，摘要/目录用罗马数字，正文用阿拉伯数字从 1 开始
3. 页眉设置：正文区域页眉为"青岛理工大学学士学位论文"
4. 清理用于手动分页的空段落

## 修复范围

- 5 个 Section 的分节符类型验证和修正
- 页码格式设置
- 页眉页脚链接设置
- 章起始位置的换页方式

## 操作步骤

### 步骤 1.1：检查和修复分节符类型

**当前状态分析**（来自 XML）：
- Section 0：封面 → 无页码，有 titlePg
- Section 1：中文摘要起始 → 页码 Roman I
- Section 2：英文摘要起始 → 页码 Roman I（与 Section 1 重复起始号）
- Section 3：目录起始 → 页码 Roman I（与 Section 1/2 重复起始号）
- Section 4：正文起始 → 页码 Arabic 1

**发现的问题**：Section 1-3 都是 Roman 起始=1，意味着摘要/英文摘要/目录的页码都是 I, I, I（三个第一页）。这显然不合理。

**修复操作**：

1. **摘要与目录共用连续罗马页码**：
   - 确认 Section 1（中文摘要）、Section 2（英文摘要）、Section 3（目录）使用"续前节"页码而非"起始页码=1"
   - 操作路径：双击页脚 → 页码 → 设置页码格式 → 选择"续前节"
   
2. **正文页码从 1 开始**：
   - Section 4（正文起始）→ 页码格式设为阿拉伯数字，起始页码=1
   - 操作路径：双击正文第一页页脚 → 页码 → 设置页码格式 → 编号格式=1,2,3…，起始页码=1

3. **封面页无页码**：
   - Section 0 已有 titlePg 属性 → 确认封面页脚为空
   - 如有页码则删除

### 步骤 1.2：设置页眉页脚

1. **确认页眉内容**：
   - Section 4（正文）页眉 = "青岛理工大学学士学位论文"
   - 确认摘要/目录区域的页眉策略（规范未明确要求，建议与正文一致或留空）
   
2. **断开节间链接**：
   - 如果不同 Section 需要不同页眉，必须在 Section 起始处断开"链接到前一节"
   - 操作路径：双击 Section 首页页脚 → 取消"链接到前一节"

### 步骤 1.3：设置章起始分页

**当前状态**：章之间没有显式的分页机制，靠自然排版分页。

**修复操作**：
1. 定位每章标题段落（"第1章 绪论"、"第2章 相关技术与理论" … "第8章 系统使用指南"、"致 谢"、"参考文献"、"附 录"）
2. 为每个章标题段落设置"段前分页"：
   - 右键段落 → 段落 → 换行和分页 → 勾选"段前分页"
   - 或：在每章标题样式（每章标题）的段落属性中添加"段前分页"
3. **不要使用手动分页符（Ctrl+Enter）**——使用样式属性更稳定

### 步骤 1.4：删除用于分页的空段落

定位章标题之前连续的空段落（CTRL+Enter 产生的分页符前后的空行），逐一删除。

## 风险等级：中

分节符修改可能影响页码和页眉。但本阶段不涉及大规模段落修改，风险可控。

## 是否影响目录：是（页码会变化）
## 是否影响页码：是（核心操作）
## 是否影响图表：否
## 是否需要人工确认：是

建议在完成分节符调整后，手动翻页检查每章首页是否正确。

## 验证方法

1. 逐页翻看：封面→摘要→目录→正文第1页→每章首页
2. 检查页码：
   - 封面：无页码
   - 摘要页：I, II, III…（连续）
   - 正文第1页：1
3. 检查页眉：
   - 正文区域每页页眉 = "青岛理工大学学士学位论文"
4. 检查每章是否从新页顶部开始

## 回滚方案

从 `backups/phase0-baseline/` 复制回 `毕业论文.working.docx`，重新开始 Phase 1。

## 阶段结束时备份

复制 `毕业论文.working.docx` → `backups/phase1-section/毕业论文.working.docx`

# Phase 2：标题与目录体系修复

## 为什么 Phase 2 必须在 Phase 3 之前

1. **目录是文档的"路标"**。如果不先修正标题体系，后续批量应用正文样式时无法区分"标题段落"和"正文段落"。
2. **样式体系的核心是标题样式**。标题定义了文档的逻辑结构（大纲），正文样式依附于这个结构。
3. **修复正文样式时需要知道哪些段落是标题**。如果先改正文样式，可能误将标题段落也改为正文字体，然后需要回退。
4. **大纲级别决定导航窗格和目录**。大纲级别修正后，Word 导航窗格才能正确显示文档结构，便于后续操作定位。

## 修复目标

1. 为自定义标题样式添加大纲级别（outlineLvl）
2. 为标题建立 Word 多级列表自动编号
3. 修复第 7 章标题的样式问题
4. 拆分 2.6 节为独立节标题
5. 重新生成自动目录

## 修复范围

- 3 个自定义标题样式的大纲级别
- 全部 8 个章标题 + 致谢/参考文献/附录标题
- 全部 34 个节标题（1.1 ~ 8.2）
- 全部 82 个小节标题（1.1.1 ~ 附录 C）
- 2.5.2 节末尾的 2.6 内容拆分
- 目录页重建

## 操作步骤

### 步骤 2.1：为自定义标题样式添加大纲级别

**前置条件**：Phase 1 完成，节结构已稳定。

**方法一（推荐，无需解包 XML）**：

1. 打开样式窗格（Ctrl+Alt+Shift+S）
2. 右键"每章标题" → 修改 → 格式 → 段落 → 大纲级别 → 选择"1 级"
3. 右键"节标题（章下）" → 修改 → 格式 → 段落 → 大纲级别 → 选择"2 级"
4. 右键"小节" → 修改 → 格式 → 段落 → 大纲级别 → 选择"3 级"
5. 确认"毕设正文"的大纲级别为"正文文本"

**验证**：打开导航窗格（Ctrl+F），应能看到完整的章/节/小节树形结构。

### 步骤 2.2：建立 Word 多级列表自动编号

1. 打开多级列表对话框：开始 → 多级列表 → 定义新的多级列表
2. 设置三级编号：

   **级别 1（链接到样式"每章标题"）**：
   - 编号格式：`第1章`（注意："第"和"章"为固定文字，1 为自动编号域）
   - 位置：居中对齐
   - 编号之后：空格

   **级别 2（链接到样式"节标题（章下）"）**：
   - 编号格式：`1.1`（包含级别 1 的编号）
   - 位置：顶格（缩进=0）
   - 编号之后：空格

   **级别 3（链接到样式"小节"）**：
   - 编号格式：`1.1.1`（包含级别 1 和 2 的编号）
   - 位置：首行缩进 2 字符
   - 编号之后：空格

3. 关键设置：在"更多"选项中，确保"正规样式编号"未勾选

### 步骤 2.3：应用自动编号并清除手动编号文字

**操作策略**：逐章进行，而非全文一次性操作。

1. 删除标题中手动输入的编号文字（如"第1章"、"1.1"、"1.1.1"）
2. 确保段落应用了正确的样式（每章标题/节标题（章下）/小节）
3. 多级列表会自动填入编号
4. **逐章验证**：从第 1 章开始，确认编号正确后再进入下一章

**特别注意**：

- "致 谢"：应用"每章标题"样式但需在多级列表中排除（右键编号 → 选择"无"）
- "参考文献"：同上
- "附 录"：同上，但需确认附录 A/B/C 的编号方案
- 附录 A/B/C 的节标题：手动输入"附录A"等文字，不使用自动编号

### 步骤 2.4：修复第 7 章标题

1. 定位正文中的"第7章  总结与展望"段落（当前为手动格式：SimHei 16pt Bold，样式=None）
2. 清除手动格式：选中段落 → Ctrl+空格（清除字符格式）→ Ctrl+Q（清除段落格式）
3. 应用"每章标题"样式
4. 确认多级列表自动填入"第7章"编号

### 步骤 2.5：拆分 2.6 节

1. 定位"2.5.2 排序类指标（NDCG@K、MRR@K）"末尾段落
2. 找到"2.6 LightGCN与EASE模型"的文本起始位置
3. 在该位置之前插入段落分隔（Enter）
4. 将新段落的样式设为"节标题（章下）"
5. 确认多级列表填入"2.6"
6. 删除原段落中残留的"2.6"手动文字
7. 将模型介绍的主体文本应用"毕设正文"样式
8. 检查后续编号：原 2.5 之后的节编号是否自动更新（应该是，因为使用了自动编号）

### 步骤 2.6：重新生成目录

1. 删除当前目录的全部内容（选中全部目录段落 → Delete）
2. 光标定位到"目录"标题下方
3. 插入 → 引用 → 目录 → 自动目录（或自定义目录，选择显示级别=3）
4. 确认目录格式：
   - 一级标题（章）：小四号宋体（与 TOC1 样式关联）
   - 二级标题（节）：小四号宋体，缩进
   - 三级标题（小节）：小四号宋体，缩进

### 步骤 2.7：修复"目录"标题样式

1. 检查"目录"标题当前样式（TOC Heading）
2. 如果字体/大小与"每章标题"不一致，改为应用"每章标题"样式
3. 在样式中手动取消其自动编号（或在多级列表中排除）

## 风险等级：高

标题体系是文档的核心骨架。自动编号设置错误可能导致全部标题编号混乱。需要逐章验证。

## 是否影响目录：是（会重建）
## 是否影响页码：间接（目录重新生成后页码可能变化）
## 是否影响图表：否（图表编号独立于标题编号）
## 是否需要人工确认：是

**必须在每章完成后人工检查编号是否正确。**

## 验证方法

1. 打开导航窗格（Ctrl+F），确认所有标题出现在树形结构中
2. 逐章检查标题编号：第1章→1.1→1.1.1 是否自动连续
3. 检查"致谢""参考文献""附录"没有被自动编号为"第9章"
4. 更新目录（F9 或右键更新域），确认所有标题出现在目录中
5. 核对目录页码与正文实际页码

## 回滚方案

从 `backups/phase1-section/` 复制回 `毕业论文.working.docx`，重新开始 Phase 2。
（跳过 Phase 1 的回滚，因为 Phase 1 已验证通过。）

# Phase 3：正文样式统一

## 为什么 Phase 3 必须在 Phase 4/5/6 之前

1. **正文格式化会改变行数/页数**。图表锚点和公式位置依赖正文位置。如果正文不稳，图表位置在后续持续漂移。
2. **行距和字体大小变化会导致页面重新排版**。全部 10000+ 字的字体从 9pt 改为 12pt 会使页数明显增加（预估增加 15-25%）。图表的页面位置将完全改变。
3. **样式统一后才能安全地增删文字**（Phase 7 的 AI 痕迹修改）。

## 修复目标

1. 将所有正文段落统一应用"毕设正文"样式
2. 全局替换非规范字体（微软雅黑 → 宋体、MS Mincho 排查）
3. 统一正文字体大小为 12pt（小四号）
4. 统一行距为 1.5 倍行距
5. 统一首行缩进为 2 字符

## 修复范围

- 全文 1166 个无样式段落
- 全文 205 个微软雅黑 Run
- 全文 156 个 MS Mincho Run
- 全文 956 个 9pt Run → 12pt
- 全文 174 个空段落

## 操作步骤

### 步骤 3.1：修改"毕设正文"样式定义（先改样式，后应用）

1. 打开样式窗格
2. 右键"毕设正文" → 修改 → 格式：
   - 字体：中文=宋体（SimSun），英文=Times New Roman
   - 字号：小四（12pt）

3. 语言修改是纯文本操作，应在格式完全稳定后进行，避免"修好格式→改文字→格式又乱了"
4. 如果 Phase 7 导致页面数变化，Phase 8（最终质量门）会检测到

## 为什么 Phase 7 不在 Phase 6 之前

如果先改 AI 痕迹再处理参考文献，正文修改可能导致引用编号偏移（增删了引用句），然后需要回头再调参考文献列表。所以顺序是：

Phase 6（修引用格式）→ Phase 7（改正文文字，可能微调引用）→ Phase 8（检查引用一致性）

## 修复目标

1. 重写高风险 AI 痕迹段落（1.1.1、1.3.2 部分、7.1、7.2）
2. 替换宣传式/夸张语言
3. 删除或改写空泛总结句

## 操作步骤

### 步骤 7.1：重写高风险 AI 痕迹段落

**1.1.1 节"三段式总结"**（当前约 5 个连续的自然段，全用"本文+动词"开头）：

改写原则：
- 合并过于碎片化的短段
- 减少"本文"开头的句子，用具体主语替代
- 将"首先/其次/最后"的机械结构改为自然的因果/递进关系
- 保留所有事实信息（MovieLens 32M、Flask、ItemCF、NCF、Hybrid、8 模型对比等）

**1.3.2 节 5 个创新点**（当前全用"(1) (2) (3) (4) (5)"的列表式）：

改写原则：
- 5 个创新点本身是合理的结构
- 在每个创新点的解释中融入更多"为什么这样做"的判断性语言
- 减少"本文+动词"的重复，用具体的工程决策描述替代

**7.1 节工作总结**（当前重复了前文的大量语句）：

改写原则：
- 总结不应是复制粘贴前文
- 提炼 3-4 个最核心的成果（而非逐条复述做了什么）
- 突出"发现了什么"而非"做了什么"
- 与 1.3.2 的创新点呼应——回答"创新点是否达到了预期效果"

**7.2 节不足与展望**（当前 5 条都用"后续可..."开头）：

改写原则：
- 每条不足需先描述"当前具体局限是什么"（带数据），再给改进方向
- 避免"后续可"的模板句式，用更明确的主语
- 合并相近的改进方向（如(2)和(3)都涉及模型扩展）

### 步骤 7.2：替换宣传式/夸张语言

逐章搜索以下词汇并替换：

| 当前表达 | 替换为 |
|----------|--------|
| "显著提升" | 给出具体数值（如"在 R@10 上提升 3.9%"），或改为"有一定提升" |
| "具有重要意义" | 删除或改为具体意义描述 |
| "具备较强的" | 改为"具有"（去掉程度修饰） |
| "完整闭环" | 改为"完整的用户反馈数据通路" |
| "较为扎实的基础" | 改为"基础知识" |
| "为后续研究奠定了基础" | 改为具体说明：提供了什么可用的基础 |

### 步骤 7.3：删除/改写空泛总结句

查找模式：
- "具有一定的参考价值" → 删除
- "在工程落地中得到广泛应用" → 如果属实，给出具体案例；否则删除
- "为...提供了有力支撑" → 改为具体说明支撑了什么

# 附录 B：修复过程中的禁忌操作

以下操作在修复过程中**绝对禁止**：

1. ❌ 全文选中后统一应用样式（会破坏标题、图表、公式的格式）
2. ❌ 使用"清除所有格式"（会丢失已有的正确格式）
3. ❌ 同时修改多个不相关的样式属性（难以定位问题来源）
4. ❌ 直接修改 XML（除非在 Phase 0 的备份已就位且确认可以回滚）
5. ❌ 使用第三方"格式刷"工具（可能引入新的样式污染）
6. ❌ 在未完成 Phase 3 前进行全文替换字体（可能误改公式和代码块）
7. ❌ 在目录未生成前手动调整页码
8. ❌ 不经备份直接覆盖 `毕业论文.working.docx`
