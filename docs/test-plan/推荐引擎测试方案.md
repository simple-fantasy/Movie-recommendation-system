## 1. 系统架构速览（测试视角）

### 1.1 推荐请求全链路

```
HTTP GET /api/recommendations?strategy=X&n=Y&recall_k=Z
│
├─ [Gate 1] 用户鉴权
│   ├─ 匿名用户 ──────────────────→ popular_fallback (anonymous_user)
│   └─ 已登录用户 → 继续
│
├─ [Gate 2] 冷启动检测
│   ├─ 无评分记录 ────────────────→ popular_fallback (cold_start)
│   └─ 有评分 → 继续
│
├─ [Route A] strategy=popular
│   └─ _get_popular_fallback(n) ──→ 热门电影 (有海报, ≥1评分)
│       └─ Cache Key: `_popular_fallback_{n}`, TTL=300s
│
├─ [Route B] strategy=itemcf
│   ├─ _itemcf_recall(user_id, ratings, n, rated_ids)
│   │   ├─ MovieSimilarity.query.filter(movie_id.in_(seed_ids))
│   │   ├─ 每种子电影取Top50相似 → 加权累加 → Top-N
│   │   └─ 返回: [(movie_id, score), ...], contributions
│   └─ _format_recommendations(ranked, ...) ──→ JSON
│       └─ 过滤: 无海报电影、placeholder 海报
│
├─ [Route C] strategy=ncf
│   ├─ ncf_engine.is_ready()? ──→ NO → itemcf_fallback
│   ├─ user in ncf_engine.user2idx? ──→ NO → itemcf_fallback
│   ├─ 候选集: 未评分热门电影 Top500
│   ├─ ncf_engine.rank(user_id, candidates, top_k=n)
│   │   └─ score() → batched forward (batch_size=256) → Top-K
│   └─ _format_recommendations(...) ──→ JSON
│
├─ [Route D] strategy=hybrid
│   ├─ Step 1: _itemcf_recall(recall_k=200) → 召回候选
│   ├─ Step 2: ncf_engine.is_ready()?
│   │   ├─ YES → _ncf_rank(candidates, top_k=n) → 重排
│   │   └─ NO  → ItemCF Top-n 直接输出 (itemcf_fallback)
│   └─ _format_recommendations(...) ──→ JSON
│
└─ [Final Gate] _make_rec_response()
    └─ 结果为空? → popular_fallback (empty_result)
```

### 1.2 关键数据结构

| 结构 | 字段 | 说明 |
|------|------|------|
| **请求参数** | `n` (int, 1-50), `strategy` (string), `recall_k` (int, 1-500) | |
| **推荐项** | `id, title, year, genres, avg_rating, rating_count, score, poster, backdrop, overview, reason, because` | `score=None` 表示热门回退 |
| **响应元数据** | `meta.actual_strategy`, `meta.fallback_reason` | 必须始终存在 |
| **because** | `[{movie_id, title, weight}, ...]` | 最多3个种子电影 |

### 1.3 依赖边界

```
推荐API
├── DB: Movie, Rating, MovieSimilarity (SQLAlchemy ORM)
├── Cache: Flask-Caching FileSystemCache (磁盘持久化)
├── NCF Engine: 单例, 线程锁, 异步加载
│   ├── ncf.pt (生产推理)
│   └── ncf_v2.pt (离线评估)
├── Auth: Flask-Login current_user
└── 外部依赖: 无 (TMDB海报已在启动时预加载)
```

## 13. 风险登记册

### 13.1 已识别风险

| ID | 风险描述 | 严重度 | 可能性 | 检测方式 | 缓解措施 |
|----|----------|--------|--------|----------|----------|
| **R01** | NCF模型路径不一致 (`ncf.pt` vs `ncf_v2.pt`) | 高 | 已确认 | 检查`ncf_engine.py:214`加载路径 vs `config.py:20`评估路径 | 统一路径或文档化差异 |
| **R02** | `torch.load(weights_only=False)` 安全隐患 | 中 | 已确认 | 安全测试X-DL-001 | 改为`weights_only=True`（需PyTorch≥1.13） |
| **R03** | `_format_recommendations`静默丢弃无海报电影 | 中 | 已确认 | 契约测试C-SC-007 | 日志记录丢弃数量; 前端不依赖精确数量 |
| **R04** | MovieSimilarity训练期间表为空 | 中 | 低 | 集成测试I-IC-001在训练期间 | 使用事务或蓝绿部署 |
| **R05** | NCF加载线程在HTTP请求中阻塞 | 中 | 低 | 性能测试P-NC-001 | 已有异步加载, 验证超时设置 |
| **R06** | 评分竞态条件 (并发创建同一user-movie评分) | 中 | 低 | 集成测试I-RT-001+002 | 已有try/except+rollback保护 |
| **R07** | Flask-Caching文件系统缓存磁盘满 | 低 | 低 | 性能测试P-ME-003 | 设置CACHE_THRESHOLD限制 |
| **R08** | NCF单例在多进程下的行为 (gunicorn workers) | 高 | 低 | 暂不测试(当前为开发服务器) | 文档化限制, 建议单worker部署 |
| **R09** | 用户评分limit=200截断导致推荐质量下降 | 低 | 中 | 质量测试Q-ED-004 | 评估不同limit值的NDCG差异 |
| **R10** | Hybrid的NCF重排返回空导致静默降级 | 中 | 中 | 集成测试I-HB-004 | 已有fallback逻辑, 验证meta正确 |
