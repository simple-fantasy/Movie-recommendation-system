### 3.2 RC-1: 路由注册缺失

**根因**: 功能迭代中移除或未实现部分页面路由和API端点，但前端或测试脚本仍引用旧URL。

**代码证据**:
```
routes.py 中:
  ✅ @bp.get("/")                       → portal.html
  ✅ @bp.get("/app")                    → app.html
  ✅ @bp.get("/movie/<int:movie_id>")   → movie.html
  ✅ @bp.post("/api/auth/register")     → API端点(非页面)
  ❌ 无 notifications 相关路由
  ❌ 无 charts 相关路由
  ❌ 无 /register 页面路由

admin_routes.py 中:
  ✅ @admin_bp.route('/api/admin/ratings/stats')   → /admin/api/admin/ratings/stats
  ✅ @admin_bp.route('/api/admin/reviews/stats')   → /admin/api/admin/reviews/stats
  ❌ 无 charts 管理路由
```

**影响Bug**: BUG-001, BUG-002, BUG-014, BUG-003c

**修复策略**: 确认功能需求 → 注册路由或更新测试URL

**非Bug项**:
- BUG-003a/b: 路由存在，测试脚本URL缺少 `/admin` 前缀
- BUG-015: 路由存在，URL拼写差异 (`/movie/` vs `/movies/`)

### 3.3 RC-2: 输入参数校验缺失

**根因**: `routes.py:929` 行 `min(int(n or 10), 50)` 无 try/except 包裹，无范围校验。

```
                    int(n) 成功
                    │
    request.args.get("n") ──┤
                            │
                    int(n) 失败 → ValueError → 500 (BUG-007)
                            │
                    int(n) = -5 → min(-5, 50) = -5
                                    │
                                    ranked[:-5] → 异常多返回 (BUG-006)
```

两个Bug共享同一个第一个无效状态：**`int()` 返回值未经验证即传入下游逻辑**。

**代码位置**: 
- Line 929: `top_n = min(int(request.args.get("n") or 10), 50)`
- Line 931: `recall_k = min(int(request.args.get("recall_k") or 100), 500)`

**影响Bug**: BUG-006, BUG-007

**修复策略**: 添加 try/except + 范围校验（5行代码），两处统一处理。

### 3.4 RC-3: 数据库索引缺失

**根因**: `ratings` 表(32M行)缺少 `(movie_id)` 复合索引，导致 `GROUP BY movie_id` 全表扫描。

**影响面**:
```
ratings (32,000,281 rows)
    │
    ├── GROUP BY movie_id ORDER BY count DESC
    │   ├── _get_popular_fallback() → 12s (BUG-009)
    │   └── NCF候选集生成 → 10s (BUG-011)
    │
    └── 可能的其他GROUP BY查询
        └── Admin Dashboard → 3.7s (BUG-005, 待验证)
```

**验证方法**: `EXPLAIN QUERY PLAN SELECT movie_id, COUNT(id) FROM ratings GROUP BY movie_id` — 预期显示 `SCAN TABLE ratings`（全表扫描）。

**代码位置**:
- routes.py:862-872 (`_get_popular_fallback` 子查询)
- routes.py:979-986 (NCF候选集查询)
- admin_routes.py:61 (dashboard聚合查询，待确认)

**影响Bug**: BUG-009, BUG-011, (BUG-005 待验证)

**修复策略**: `CREATE INDEX idx_ratings_movie_id ON ratings(movie_id, id)` — 1行SQL。预期12s→<100ms。

### 3.5 RC-4: NCF 模型质量

**根因**: NCF 模型训练过程存在问题，导致两个症状：
1. **BUG-008**: 模型输出 logits 过大 → sigmoid 饱和在 ≈1.0 → 所有候选分数无区分度
2. **BUG-010**: 训练数据快照不包含后来创建的管理员用户(admin=200949)

**可证伪假设**:

| # | 假设 | 验证方法 |
|---|------|----------|
| H1 | 训练过度(epochs过多)导致过拟合 | 查看训练日志中的val NDCG曲线 |
| H2 | 负采样不足(neg_ratio=1) | 尝试neg_ratio=4重训 |
| H3 | 学习率过大导致logits爆炸 | 检查lr=0.001是否合适 |
| H4 | 训练时用户ID范围截断了admin | 检查训练脚本中的用户过滤条件 |

**代码位置**:
- `ncf_engine.py:214` — `torch.load(..., weights_only=False)` (安全隐患)
- `backend/scripts/train_ncf.py` — 训练脚本
- `backend/artifacts/ncf_meta.json` — user2idx 不含 200949

**影响Bug**: BUG-008, BUG-010

**修复策略**: 
- 短期: 重训模型 + 包含admin用户 + 调整超参
- 长期: 统一 `ncf.pt` vs `ncf_v2.pt` 路径，消除双模型混淆

### 3.6 RC-5: 测试基础设施缺陷

**根因**: 6个测试脚本均采用 `if response.status_code == 200: print("✓")` 模式，无断言、无失败计数、无非零退出码。

**代码证据** (test_all_modules.py):
```python
response = client.get('/api/notifications')
data = response.get_json()
if response.status_code == 200:
    print(f"   ✓ 获取通知列表成功")
# ← 没有 else 分支! 404时静默忽略
```

**影响**: BUG-001/002/003 因测试脚本缺陷长期未被发现。任何404错误都被标记为"通过"。

**影响Bug**: BUG-004

**修复策略**: 改造6个脚本为 pytest 或至少添加 assert + 失败计数 + 非零退出码。

### 3.7 RC-6: 功能缺口

**根因**: 两个功能的"最后一步"未完成——核心逻辑存在但缺少用户友好的外壳。

**BUG-012**: `POST /api/auth/register` 重复用户名返回400但无 `"用户名已存在"` 提示
**BUG-013**: 只有 `POST /api/ratings` 用于创建/更新，无 `GET` 端点读取评分列表

**影响Bug**: BUG-012, BUG-013

**修复策略**: 
- BUG-012: 在注册失败时返回具体原因
- BUG-013: 新增 `GET /api/ratings` 端点或确认前端不需要

#### RC-3: DB索引 (BUG-009/011/005)

```

├── 直接影响
│   ├── 读性能: 12s → 预估 <100ms (GROUP BY 走索引)
```
