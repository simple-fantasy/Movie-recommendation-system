### Step 1.1 — 创建 ratings(movie_id, id) 复合索引

| 字段 | 内容 |
|------|------|
| **目标** | 为 ratings 表添加 (movie_id, id) 复合索引，消除 GROUP BY movie_id 全表扫描 |
| **涉及Bug** | BUG-009 (popular 12s), BUG-011 (NCF 10s) |
| **涉及文件** | 数据库：`ratings` 表 |
| **风险等级** | 🟢 低 — 纯性能优化，不改变查询结果 |
| **依赖关系** | 无前置依赖。后续 Phase 2/3 不依赖此 Phase |
| **修改范围** | 执行1条 DDL 语句 |

#### 修改内容

```sql
-- 需要执行的DDL (SQLite方言)
CREATE INDEX idx_ratings_movie_count ON ratings(movie_id, id);

-- MySQL方言 (生产环境)
-- CREATE INDEX idx_ratings_movie_count ON ratings(movie_id, id);
```

#### 执行说明

- **位置**: 数据库迁移脚本或在应用启动时通过 `db.create_all()` 后执行
- **SQLite**: 索引创建期间短暂写锁（30-60秒）
- **MySQL**: 使用 `ALGORITHM=INPLACE, LOCK=NONE` 避免锁表
- **磁盘空间**: 新增约 200-400MB

#### 验证方法

```python
# 验证1: 检查索引是否创建成功
# SQLite: PRAGMA index_list('ratings');
# 预期: 列表中包含 idx_ratings_movie_count

# 验证2: 确认查询计划使用索引
# EXPLAIN QUERY PLAN
# SELECT movie_id, COUNT(id) as cnt, AVG(rating) as avg_r
# FROM ratings GROUP BY movie_id
# HAVING COUNT(id) >= 50 ORDER BY cnt DESC LIMIT 300;
# 预期: USING INDEX (不再 SCAN TABLE)

# 验证3: 性能对比测试
# 运行 scripts/tests/manual/test_perf_baseline.py
# 预期: popular fallback 冷查询 < 100ms (原 12,000ms)
#        NCF 候选查询 < 100ms (原 10,000ms)
```

#### 回滚方案

```sql
DROP INDEX IF EXISTS idx_ratings_movie_count;
-- 回滚后性能恢复为 10-12s，功能不受影响
```

#### 注意事项

- 如使用 Alembic 管理迁移，需生成对应的迁移脚本
- 索引名需与现有索引不冲突
- 生产环境 MySQL 5.7 确认 InnoDB 引擎支持 online DDL

### Step 2.1 — 修复 `n` 和 `recall_k` 参数校验

| 字段 | 内容 |
|------|------|
| **目标** | 为推荐API的 `n` 和 `recall_k` 参数添加完整的输入校验，消除500错误和数值绕过 |
| **涉及Bug** | BUG-006 (n=负数绕过), BUG-007 (n=abc→500) |
| **涉及文件** | `backend/app/routes.py:929,931` |
| **风险等级** | 🟡 中 — API 契约变更（非法参数从"静默处理/500"变为"400友好错误"） |
| **依赖关系** | 无前置依赖 |

#### 现状代码

```python
# routes.py:927-931 (当前代码)
@bp.get("/api/recommendations")
def recommend():
    top_n = min(int(request.args.get("n") or 10), 50)         # ← BUG-006/007
    strategy = request.args.get("strategy", "itemcf")
    recall_k = min(int(request.args.get("recall_k") or 100), 500)  # ← 同类缺陷
```

#### 修改方案

```python
# routes.py:927-935 (修复后)
@bp.get("/api/recommendations")
def recommend():
    # ── n 参数校验 ──
    try:
        top_n = int(request.args.get("n") or 10)
    except (ValueError, TypeError):
        return jsonify({"error": "参数 n 必须为整数，取值范围 1-50"}), 400
    if top_n < 1 or top_n > 50:
        return jsonify({"error": f"参数 n={top_n} 超出范围，取值范围 1-50"}), 400

    strategy = request.args.get("strategy", "itemcf")

    # ── recall_k 参数校验 ──
    try:
        recall_k = int(request.args.get("recall_k") or 100)
    except (ValueError, TypeError):
        return jsonify({"error": "参数 recall_k 必须为整数，取值范围 1-500"}), 400
    if recall_k < 1 or recall_k > 500:
        return jsonify({"error": f"参数 recall_k={recall_k} 超出范围，取值范围 1-500"}), 400
```

#### 修改点统计

| 项目 | 数值 |
|------|------|
| 修改文件 | 1 (`routes.py`) |
| 修改行 | 2行 → 12行 (+10行) |
| 新增返回码 | 400 (两种场景) |
| API契约变更 | n=-5 → 400(原200返回95项) / n=abc → 400(原500) |

#### 验证方法

```bash

curl "http://127.0.0.1:5000/api/recommendations?n=10"        # → 200, 10项
curl "http://127.0.0.1:5000/api/recommendations?n=50"        # → 200, 50项
curl "http://127.0.0.1:5000/api/recommendations?n=1"         # → 200, 1项
curl "http://127.0.0.1:5000/api/recommendations?recall_k=100" # → 200

# 验证2: BUG-006 修复确认
curl "http://127.0.0.1:5000/api/recommendations?n=-5"        # → 400
curl "http://127.0.0.1:5000/api/recommendations?n=0"         # → 400

# 验证3: BUG-007 修复确认
curl "http://127.0.0.1:5000/api/recommendations?n=abc"       # → 400
curl "http://127.0.0.1:5000/api/recommendations?n="          # → 200 (使用默认值10)

# 验证4: recall_k 同类修复
curl "http://127.0.0.1:5000/api/recommendations?strategy=hybrid&recall_k=-100" # → 400
curl "http://127.0.0.1:5000/api/recommendations?strategy=hybrid&recall_k=abc"  # → 400
curl "http://127.0.0.1:5000/api/recommendations?strategy=hybrid&recall_k=600"  # → 400
```

#### 回滚方案

```python
# 还原为原始代码:
top_n = min(int(request.args.get("n") or 10), 50)
recall_k = min(int(request.args.get("recall_k") or 100), 500)
```

#### 兼容性影响

- 前端正常使用不受影响（前端只用正整数 n=10/20/50）
- 如果有外部API消费者依赖 `n=-5` 的特殊行为 → 影响（极低概率）
