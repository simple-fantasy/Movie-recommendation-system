## 5. 关键发现与根因分析

### 5.1 DB性能瓶颈（BUG-009/011）— 最高优先级

**症状**: 首次推荐请求耗时 10-12 秒

**根因追踪过程**:
1. Step 1.2: 发现匿名popular请求 12.6s → 初步假设 NCF 加载阻塞
2. Step 1.3: 实测 NCF `load()` 仅 0.37s → **推翻原假设**
3. Step 1.4: 精确测量 `_get_popular_fallback()` 冷查询 = 12.5s → **定位到DB层**
4. Step 3.1: 分解 NCF 请求，确认 9.6s/9.64s = 99.6% 在 DB → **精确定位**

**根因**: `ratings` 表(32M行)缺少 `(movie_id)` 复合索引，导致 `GROUP BY movie_id ORDER BY count DESC` 全表扫描。

**影响面**: `_get_popular_fallback()` 和 NCF 候选集生成两条路径。

**修复**: `CREATE INDEX idx_ratings_movie_count ON ratings(movie_id, id);` — 预期将 10s 降至 <100ms。

### 5.2 NCF 模型质量（BUG-008）

**症状**: demo用户 NCF score 分布 0.9988~0.9999，标准差异常小，评分无区分度。

**影响**: Hybrid 策略的重排阶段近乎随机打乱 ItemCF 结果，NCF 独立推荐无法体现个性化。

**可能根因**:
1. Sigmoid 饱和——训练过度或学习率不当导致 logits 过大
2. 负采样不足——模型"学会"对所有 item 打高分
3. 训练/验证数据重叠

**需要**: 重训 NCF 模型或调整训练超参数。

### 5.3 参数校验缺失（BUG-006/007）

**根因**: `routes.py:929` 行 `min(int(n or 10), 50)` 无 try/except 包裹。

- `n=-5` → `min(-5, 50) = -5` → Python 切片 `[: -5]` 语义 = "除最后5项外全部"
- `n=abc` → `int("abc")` → 未捕获 ValueError → 500

**修复**: 添加显式参数校验，5行代码。

### 5.4 API路由缺失（BUG-001/002/003/014/015）

7个Bug涉及缺失的路由端点，可能原因：功能在迭代中移除但前端或测试脚本未同步更新。需确认是"故意移除"还是"遗漏"。
