# CineMatch 电影推荐系统 — 全面测试方案

> 适用场景：毕业设计论文 / 毕业答辩
> 系统名称：CineMatch（基于协同过滤与深度学习的混合推荐系统）
> 技术栈：Flask + SQLAlchemy + PyTorch + scikit-learn + Vue 3 + Bootstrap 5

---

## 一、测试目标

| 目标编号 | 目标描述 |
|----------|----------|
| O1 | 验证推荐引擎（ItemCF / NCF / Hybrid）的推荐质量满足设计指标 |
| O2 | 验证所有 API 端点的功能正确性和错误处理健壮性 |
| O3 | 验证前端页面交互逻辑正确、无 JS 错误、UI 一致 |
| O4 | 验证系统安全性（认证、授权、输入校验、XSS/SQL 注入防护） |
| O5 | 验证系统性能（响应时间、并发能力、缓存效率） |
| O6 | 验证数据一致性和持久化正确性 |
| O7 | 验证系统可用性和故障恢复能力 |

### 4.6 推荐质量评估（离线指标）

#### TC-EVAL-001: ItemCF 离线评估

| 指标 | 目标值 | 说明 |
|------|--------|------|
| Precision@10 | ≥ 0.05 | 前10推荐中相关物品比例 |
| Recall@10 | ≥ 0.08 | 相关物品被推荐的比例 |
| NDCG@10 | ≥ 0.06 | 归一化折损累积增益 |
| Coverage | ≥ 0.30 | 推荐覆盖的物品比例 |

**测试方法**: 运行 `python -m backend.scripts.evaluate_models --models itemcf --k 10`

#### TC-EVAL-002: NCF 离线评估

| 指标 | 目标值 | 说明 |
|------|--------|------|
| HR@10 (Hit Rate) | ≥ 0.15 | 前10推荐命中率 |
| NDCG@10 | ≥ 0.08 | 归一化折损累积增益 |
| Val Loss | < 0.35 | 验证集损失 |

**测试方法**: 训练时在控制台查看输出; 运行 `python -m backend.scripts.quick_eval.py`

#### TC-EVAL-003: 对比分析

| 测试内容 | 方法 |
|----------|------|
| ItemCF vs NCF vs Hybrid 对比 | `python -m backend.scripts.evaluate_models --models all --k 10` |
| 冷启动场景各策略对比 | 构造无历史用户, 比较 Popular vs 各策略回退效果 |
| 不同召回量对 Hybrid 效果的影响 | recall_k ∈ {50, 100, 200} 对最终推荐质量的影响 |

## 八、缺陷严重级定义

| 级别 | 定义 | 示例 | 处理要求 |
|------|------|------|----------|
| **P0-Critical** | 系统崩溃 / 数据丢失 / 安全漏洞 | 注册失败, 推荐接口 500, SQL 注入 | 立即修复, 阻止上线 |
| **P1-High** | 核心功能异常 / 用户体验严重受损 | 评分无法提交, 搜索结果为空 | 必须修复 |
| **P2-Medium** | 非核心功能异常 / 轻微体验问题 | 海报加载失败无 fallback | 排期修复 |
| **P3-Low** | 样式偏差 / 文案错误 / 优化建议 | 按钮颜色偏差, 提示文案不友好 | 记录, 可选修复 |

## 九、验收标准

| 标准编号 | 标准 | 阈值 |
|----------|------|------|
| AC1 | P0 缺陷数 | **0** |

### 11.2 答辩可能被问到的问题预演

| 问题 | 回答要点 |
|------|----------|
| **为什么选择 ItemCF + NCF 混合策略？** | ItemCF 可解释性强、冷启动友好; NCF 捕捉非线性交互; Hybrid 互补, ItemCF 召回 + NCF 精排 |
| **冷启动问题如何解决？** | Popular 兜底; 新用户无评分 → 热门推荐; NCF 用户不在训练集 → 自动回退 ItemCF |
| **系统性能优化手段？** | Flask-Caching FileSystemCache(60s-600s); ItemCF 预计算相似度存入 DB; NCF batch inference; db.session 批量查询避免 N+1; 索引优化 |
| **如何评估推荐质量？** | 离线评估: HR@K / NDCG@K / Precision@K / Recall@K; 在线反馈: 用户 like/dislike 记录 |
| **数据库设计关键考量？** | 索引设计(ratings timestamp/user_id/movie_id, movies genres/avg_rating); UniqueConstraint 防重复; cascade delete 保持引用完整性; JSON 字段存灵活结构(用户画像) |
| **系统的可扩展性？** | 推荐策略可插拔(新增策略只需注册到 /api/recommendations); 前后端分离架构(Vue 组件化); 配置文件驱动(.env + Pydantic 校验) |
| **NCF 模型训练流程？** | MovieLens 加载 → Leave-last-one-out 划分 → 负采样 → BCE Loss + Adam → Early Stopping(patience=3) → 保存 ncf.pt + ncf_meta.json |
| **发现的 Bug 及修复？** | 双重 JSON.stringify 导致 10+ API 调用失败; behavior_tracker 跨线程 session 崩溃; 竞态条件导致数据不一致; 管理员缓存跨用户泄漏; 错误详情泄漏内部信息 |
