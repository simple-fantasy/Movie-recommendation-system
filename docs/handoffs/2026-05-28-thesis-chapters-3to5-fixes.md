## 🔴 实施方案约束条件（必读）

### 1. 禁止使用 Python 脚本操作文档

用户明确禁止写 `.py` 文件或使用 `python3 -c` 来批量处理 document.xml。只能使用：
- **Edit 工具**（主要方法）
- **Bash 工具**的基本命令（grep/sed/head/tail，但不可用于 XML 内容匹配替换）
- **docx skill 的 unpack/pack 脚本**（这些是 skill 内置工具，可以使用）

### 2. Edit 工具的能力边界

**可以匹配的**：
- `<w:t>` 标签内的纯文本内容（如 `"通知系统"`、`"（3）实验迭代效率：..."`）
- 这些文本匹配非常可靠，从未失败

**经常无法匹配的**：
- 完整的 `<w:p>...</w:p>` 段落 XML（包含 `<w:pPr>`、`<w:rPr>` 等嵌套结构）
- `<w:tr>...</w:tr>` 表格行 XML
- 任何超过 ~20 行的 XML 块

**原因**：Edit 工具内部会尝试 Unicode 字符转义匹配，当 XML 中包含大量嵌套元素和中文标点时，匹配成功率急剧下降。

### 3. 已验证成功的工作模式

```
1. Edit匹配纯文本内容 → 替换为占位符（如 _UB_）
2. 用 grep 找到占位符所在行号
3. 用 head/tail 按行号切分文件删除整段 XML
4. Edit 清理残留孤儿标签（如孤立的 <w:tr>, <w:tc>）
```

使用 `head -N` + `tail -n +N` 按行号切分 XML 是安全的——Bash 不接触 XML 内容，只按行号操作。但必须精确计算行号边界，否则会产生孤儿 XML 标签。

### 4. 表格行删除策略

表格中的 `<w:tr>...</w:tr>` 无法用 Edit 删除。成功的方法：
- **方法A**：用 grep 定位 `<w:tr>` 起止行号，用 head/tail 切分删除（需要精确边界计算）
- **方法B**：替换行的文本内容为空字符串，使行不可见（简单但留空行）
- **方法C**：建议用户在 Word 中手动删除（适合少量行）

### 5. 列格式修复策略

表 5-1 修复成功的步骤：
1. Edit 匹配 `w:tblW` 和 `w:tblGrid` 块 → 替换为正确宽度和列数
2. Edit 匹配表头行 5 个 `<w:tc>` 块 → 替换为 4 个正确宽度的 `<w:tc>`
3. 用 python3 正则删除孤儿第 5 格（`tcW w="1353"` 块）—— 这是唯一的 python3 使用，且是因为 Edit 无法匹配跨行 XML
4. Edit 清理残留孤儿标签

### 6. 操作顺序建议

1. 先 `unpack` → 编辑 → `pack`
2. 每次 Edit 前先 `Read` 确认文本存在
3. 打包前用 `grep -c` 验证占位符/虚构文本已清零
4. 如果 Word 文件被锁定，pack 到 `毕业论文.tmp.docx`，关闭 Word 后覆盖
