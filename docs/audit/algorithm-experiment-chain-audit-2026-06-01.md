## 一、算法链审计

### 1.1 五算法全链路追踪

论文涉及五种方法，按在线/离线角色分两组：

| 角色 | 方法 | 范式类别 | 训练方式 | 推理方式 |
|---|---|---|---|---|
| 在线服务 | ItemCF | 基于记忆的协同过滤 | 余弦相似度 + TopK截断 → MySQL | 批量IN查询 → 内存加权聚合 |
| 在线服务 | NCF | 基于表示学习的深度学习 | Embedding + MLP + BCE + 负采样(1:4) | NCFEngine单例异步加载 → rank() |
| 在线服务 | Hybrid | 级联（记忆+表示学习） | ItemCF训练 + NCF训练各自独立 | ItemCF召回 → NCF重排 |
| 仅离线 | EASE | 解析解 | 闭式最小二乘 (G+λI)⁻¹G, λ=500 | 权重矩阵B直接计算 |
| 仅离线 | LightGCN | 图卷积 | 3层图卷积 + BPR损失 | Embedding内积 |

### 1.3 算法链路完整性

每个算法的"出现→原理→实现→实验→结论"链路追踪：

**ItemCF**：
```
1.2.1 文献(Amazon 2003, Sarwar) → 2.2 原理(调整余弦/O(N²)→O(NK)) 
→ 3.2.2 需求(评分幂等性) → 4.2 存储(movie_similarity表) 
→ 5.2.1 实现(kneighbors+批量IN) → 5.2.2 召回(相似度×评分加权) 
→ 5.6.4 解释(because字段) → 6.2 对比设置 → 6.3.1 结果(NDCG=0.049最优) 
→ 6.4.3 消融(per_seed_limit=10优于50) → 8.1 结论
```
**链路完整** ✅ — 从文献出处到实验结论，无断点。

**NCF**：
```
1.2.2 文献(He 2017, GMF/MLP/NeuMF, BCE/BPR) → 2.3 原理(内积→MLP) 
→ 5.1.2 切分(train/val/test) → 5.1.3 负采样(碰撞检测) 
→ 5.3.1 结构(64+256+BCEWithLogitsLoss) → 5.3.2 训练(早停+分块前向) 
→ 5.3.3 部署(ncf_v2.pt+ncf_v2_meta.json+NCFEngine) 
→ 5.4.1 级联边界(IndexError→过滤→日志) 
→ 5.5 优化(批量化/页锁定/cuDNN) 
→ 6.2 对比设置 → 6.3.1 结果(R@10=0.0664) → 8.1 结论
```
**链路完整** ✅。5.3.2 如实标注了 NDCG 口径差异（采样评估0.81 vs 全量排序0.041）。

**Hybrid**：
```
2.4 原理(三种融合方式取舍) → 5.4.1 实现(召回→过滤→重排→去重) 
→ 5.4.2 策略切换(strategy参数+回退) → 6.2 对比设置(recall_k=200) 
→ 6.3.1 结果(R@10=0.0689, NDCG=0.0421) 
→ 6.4.3 消融(recall_k=50时NDCG反超ItemCF) 
→ 6.4.4 小结(默认配置非最优) → 8.1 结论
```
**链路完整** ✅。特别注意：实验揭示默认参数(recall_k=200)非最优，论文诚实报告了这一发现。

**EASE & LightGCN**：
```
1.3.1 选型(外部参照,离线对比) → 2.6 原理(闭式解/图卷积) 
→ 6.2 对比设置 → 6.3.1 结果(EASE Coverage=0.658; LightGCN NDCG=0.0338) 
→ 8.1 结论(EASE精度-覆盖率最佳平衡)
```
**链路完整** ✅。两个外部模型不接入在线服务，但离线评估链路与其他模型一致。

### 1.4 算法链发现的问题

**A1. P324 遗留旧文本**：`混合推荐策略采用"召回---重排"的级联架构。先拿到当前用户的 ID，调 ItemCF 的 get_candidates(user_id, k=recall_k) 拉候选列表`

此句为旧 AI 模板文本。P335（降级逻辑段）也保留了旧风格（"该设计既便于实验对比，也便于后续扩展更多策略与模型"）。这两处在 5.4 节降重时遗漏，与周围重写段落风格不统一。

**风险**：低。不造成逻辑矛盾，仅风格不一致。AIGC 检测可能触发。

**A2. neg_ratio=4 的"最优值"声明无消融支撑**：P301 说"消融实验里 neg_ratio=4 是当前最优值"，但第6章消融实验实际只测试了 recall_k 和 per_seed_limit 两个参数，没有对 neg_ratio 做消融扫描。

**风险**：中。答辩时若被问"neg_ratio=4 的最优性如何验证"，无法指向具体实验数据。建议将"消融实验里 neg_ratio=4 是当前最优值"改为"neg_ratio=4 是工程上的经验取值，未做消融扫描"。

### 1.5 算法链总评

**完整**。五种方法的"出现→原理→实现→实验→结论"链路均可完整追踪，无断裂、无遗漏。仅 A2（neg_ratio 声明过度）为可修正的逻辑瑕疵。

## 二、实验逻辑链审计

### 2.1 "假设→设计→执行→解读"全链路

```
假设层（第1章）
  ├── Q1: ItemCF vs DL 在相同数据上的真实差距
  ├── Q2: 级联架构是否有正向增益
  └── Q3: 不同范式(EASE/解析解, LightGCN/图)的相对位次
        │
        ▼
设计层（第6章 6.1-6.2）
  ├── 数据: 三层时间切分 → 过滤 → C_all=13,304 → 10,000测试用户
  ├── 基线: Random + Popularity(下界) + Oracle(上界)
  ├── 对比: 8方法 × 统一候选集 × 全量排序
  ├── 指标: 排序精度5项 + 多样性5项
  └── 显著性: Wilcoxon Signed-Rank + Bonferroni-Holm
        │
        ▼
执行层（6.3-6.4）
  ├── 6.3.1 排序精度: ItemCF > EASE > Hybrid > NCF > LightGCN
  ├── 6.3.2 多样性: EASE ≫ ItemCF ≫ NCF ≫ LightGCN
  ├── 6.3.3 用户分层: Warm用户NDCG全部高于Hot, EASE最稳定
  ├── 6.3.4 显著性: 全部p<0.01, Cohen's d 0.03-0.12
  └── 6.4 消融: recall_k=50最优, per_seed_limit=10最优
        │
        ▼
解读层（6.3.5 + 第8章）
  ├── 结论1: ItemCF排序最优(证据充分)但不能推广为"CF>DL"
  ├── 结论2: EASE覆盖最优(Coverage 6.4×), 代价是矩阵求逆O(n³)
  ├── 结论3: Hybrid受限于召回, 改进方向是提升召回覆盖率
  └── 三个盲区: NCF调参不充分/离线≠在线/数据时效性
```

### 2.3 实验逻辑链发现的问题

**E1. per_seed_limit 消融仅测了 ItemCF 自身，未测其对 Hybrid 的影响**

消融实验设计为两组独立测试：
- Experiment 1: 动 recall_k，看 Hybrid 的 NDCG 变化
- Experiment 2: 动 per_seed_limit，看 **ItemCF 自身**的 NDCG 变化

两组实验没有交叉——per_seed_limit=10 时 Hybrid 的 NDCG 是多少？论文没有回答。P486 将两组消融的结论合并为一个方向性建议（"per_seed_limit=10, recall_k=50"），但这一组合在实验中没有被联合评估过。

**风险**：中。结论方向可能正确，但证据不完整。答辩时可被追问"per_seed_limit=10 且 recall_k=50 的 Hybrid NDCG 是多少？"。

**E2. 6.3.3 用户分层分析的"Warm/Hot比值"概念未被 Ch2 指标章定义**

P459（6.3.3）引入了"Warm/Hot比值"作为模型稳定性指标，但第2章评价指标部分未定义此概念。读者在第6章首次遇到这个比值时需要从上下文推断其含义。

**风险**：低。上下文可推断，但不严谨。

**E3. 消融实验使用 2,000 用户（全量评估的 1/5）**

P473 明确标注"基于2,000名测试用户（从10,000名全量测试用户中按用户ID排序取前2,000名，seed=42）"。这个 20% 子采样在论文中已说明但未讨论其统计影响——2,000 用户上的指标方差是否足以支撑结论？未做 bootstrap 或重复采样验证。

**风险**：低。消融实验的目标是趋势判断而非绝对精度，2,000 用户通常足够。但严格性不足。

**E4. P421 "Oracle 的 NDCG@10 达到 1.0" 的前提已被 P417 澄清，但上下文距离较远**

P417（6.2.1）解释了 Oracle=1.0 是因为评估协议过滤了 C_all 外用户。P424（6.3.1）报告 Oracle=1.0。两段之间隔了 6.2.2（评估协议参数表）、6.3.1 开头（多模型对比结果叙述）共约 400 字。读者从 P424 读到 Oracle=1.0 时可能已忘记 P417 的限定条件。此问题已在审计修复 Op1 中缓解（P417 补了桥接），但两段间距仍较大。

**风险**：低。不构成矛盾，仅可读性问题。

### 2.4 实验结论边界限定评估

论文在第6章和第8章对结论做了明确的边界限定：

| 可能被过度推广的结论 | 论文自身的限定 | 限定位置 |
|---|---|---|
| "ItemCF 优于深度学习" | "不能说 DL 在推荐上不如 CF，只能说在这个数据条件、这个评估协议下" | P465 (6.3.5) |
| "EASE 是最优模型" | "排序精度和覆盖率的最优解分属不同模型，不是谁更好的问题，是要什么的问题" | P438 (6.3.2), P15 (摘要) |

**边界限定评估：充分。** 论文在每一个可能被过度解读的结论处都标注了前提条件和适用范围。
