## 二、模型清单

### 2.1 全部模型（7 个）

| 模型 | 全称 | 类型 | 训练方式 | 参数量 | 训练时间 |
|------|------|------|----------|--------|----------|
| **Popularity** | 全局热门推荐 | 非个性化基线 | 统计评分次数 | 0 | 即时 |
| **Random** | 随机推荐 | 随机基线 | 无 | 0 | 即时 |
| **ItemCF** | 基于物品的协同过滤 | 传统协同过滤 | 余弦相似度 + 用户均值归一化 | sims: 13K×50 | ~40s CPU |
| **NCF (GMF)** | 神经协同过滤 | 深度学习（MLP） | PyTorch GPU, Adam, BCE loss | 18.3M (32d emb/128h/3层MLP) | ~30min GPU |
| **LightGCN** | 轻量图卷积网络 | 深度学习（图神经网络） | PyTorch GPU, Adam, BPR loss, 3层图卷积 | 18.3M (64d emb) | ~30min GPU |
| **EASE** | 线性自编码器 | 线性模型（闭式解） | NumPy CPU, 矩阵求逆 | 16K×16K 权重矩阵 | ~1min CPU |
| **Hybrid** | ItemCF 召回 + NCF 重排 | 混合管道 | 组合现有模型 | 0 | 即时 |

### 2.2 模型架构细节

#### ItemCF
```
输入: 用户历史评分向量
计算: weighted-sum(余弦相似度 × 评分归一化值)
      over 全量 unseen 物品
超参: per_seed_limit=50, sim_topk_per_movie=50, normalize=True
排序: Top-K by weighted sum
```

#### NCF (GMF)
```
User ID ─→ User Embedding (32d)  ─┐
                                   ├→ Concat (64d) → Linear(64,128)+ReLU
Item ID ─→ Item Embedding (32d)  ─┘                    → Linear(128,64)+ReLU
                                                       → Linear(64,1) → Sigmoid → Score
训练: BCE loss, Adam(lr=0.001), neg_ratio=1, batch_size=4096
早停: val NDCG@10 不再提升 10 轮
```

#### LightGCN
```
Layer 0: E^(0) = Xavier init (285K × 64)
Layer 1: E^(1) = D^(-1/2) A D^(-1/2) × E^(0)  ← 1-hop邻居聚合
Layer 2: E^(2) = D^(-1/2) A D^(-1/2) × E^(1)  ← 2-hop邻居聚合
Layer 3: E^(3) = D^(-1/2) A D^(-1/2) × E^(2)  ← 3-hop邻居聚合
Final:   E = mean(E^(0), E^(1), E^(2), E^(3))
Score:   user_emb · item_emb

训练: BPR loss, Adam(lr=0.005), weight_decay=1e-6
优化: epoch级传播（每epoch仅1次全图传播），手工梯度累积+Adam更新
早停: val R@10 不再提升 15 轮
最佳: epoch 7, val R@10=0.7407 (100-candidate pool)
```

#### EASE
```
X: 200K×16K 用户-物品交互矩阵（隐式反馈二值化）
G = X^T X                       ← 物品共现矩阵 (16K×16K)
P = (G + λI)^(-1)               ← 正则化求逆, λ=500
B = P × G                       ← 物品→物品权重矩阵
diag(B) = 0                     ← 强制排除自推

推理: scores = B × x_u           ← 用户交互向量 × 权重矩阵
排序: Top-K by scores
```

#### Hybrid (ItemCF + NCF)
```
输入: 用户历史
阶段1: ItemCF recall → Top-200 候选
阶段2: NCF rerank → Top-10
回退: NCF 不可用时 → ItemCF recall 前 10
```

## 三、评估结果

### 3.1 全量 80K 协议（真实推荐场景）

**协议：10,000 用户，全量排序，≥5 交互，1 test item**

| 排名 | 模型 | P@10 | R@10 | NDCG@10 | MAP@10 | MRR@10 | Coverage | ILS↓ | 类型 |
|:--:|------|------|------|---------|--------|--------|----------|------|------|
| 1 | **EASE** | **0.0103** | **0.1032** | **0.0546** | **0.0399** | **0.0399** | **0.1010** | **0.0253** | 线性自编码器 |
| 2 | ItemCF | 0.0089 | 0.0890 | 0.0476 | 0.0351 | 0.0351 | 0.0155 | 0.1480 | 传统协同过滤 |
| 3 | LightGCN | 0.0057 | 0.0569 | 0.0291 | 0.0207 | 0.0207 | 0.0025 | 0.1333 | 图神经网络 |
| — | Random | 0.0000 | 0.0002 | 0.0001 | 0.0000 | 0.0000 | — | — | 基线 |

**关键结论：**
- EASE 比 ItemCF 高 16%（Recall），Coverage 高 6.5 倍（0.101 vs 0.016）
- EASE vs ItemCF: p < 0.0004（Wilcoxon 检验），Cohen's d = 0.035
- LightGCN 所有指标均劣于 ItemCF 和 EASE，Coverage 仅 0.0025
- EASE 的优势来自长尾覆盖——它能推荐更多冷门电影

**数据源：** `backend/artifacts/full_ranking_final.json`

## 八、关键发现与论文叙事

### 8.1 核心发现

1. **EASE 是全场最佳单模型。** 在全量 80K 候选协议中，EASE R@10=0.1032，比 ItemCF 高 16%，Coverage 高 6.5 倍。统计显著（p<0.0004）。

2. **深度学习方法在 MovieLens 上未能超越传统方法。** NCF (R@10=0.066) 和 LightGCN (R@10=0.053) 均低于 ItemCF (R@10=0.077)。这一发现与学术文献中"纯 CF 方法在稠密评分数据集上常优于早期 DL 方法"的结论一致。

3. **EASE 的优势来自长尾覆盖。** 在 C_all=13K 交集空间上，EASE 与 ItemCF 差距缩小到 1.8%。C_all 过滤掉了 EASE 擅长的长尾/冷门物品，暴露了 EASE 对冷门物品的独特覆盖能力。

4. **LightGCN 表现最差，甚至不如 Popularity 基线。** 图神经网络在该数据集上没有展现出结构优势。

5. **模型复杂度与效果成反比。** ItemCF（余弦相似度）和 EASE（闭式最小二乘）都不需要梯度下降训练，但效果超过需要 GPU 训练的 NCF 和 LightGCN。

### 8.3 答辩准备要点

- **Q: 为什么 EASE 比深度学习模型好？** → EASE 在整个共现矩阵上做全局最小二乘，能"看到"所有物品之间的关系。DL 方法每个训练步只看几个采样样本对，在稠密数据上全局信息比局部采样重要。
- **Q: Hybrid 为什么没超过 ItemCF？** → 当前 Hybrid 的 ItemCF 召回阶段设置了 recall_k=100，候选集覆盖有限。后续可通过增大 recall_k、引入多路召回、替换 EASE 作为重排模型来改进。
- **Q: LightGCN 为什么表现最差？** → 图传播 3 层可能过平滑；训练使用了手工梯度而非 autograd 完整反向传播；BPR 采样训练可能不如 EASE 的全局优化。
- **Q: 论文标题的"融合"还成立吗？** → 成立。论文贡献是设计并验证了 ItemCF→NCF 两阶段混合管道架构。虽然单模型对比中 EASE 最优，但混合管道的架构设计为后续替换更强召回/重排模型提供了框架。

## 九、已解决的技术问题

| 问题 | 解决方案 | 影响 |
|------|----------|------|
| DB 32M 行加载极慢 | pickle 缓存 + raw cursor 流式导出 | 加载从 5-10min → 3s |
| LightGCN 全图传播×每batch 极慢 | epoch 级传播（每 epoch 仅 1 次 propagation） | 每 epoch 从 40min → 50s |
| LightGCN backward 二次释放 | 手工梯度累积 + Adam 更新 | 消除 autograd 重复释放 |
| 评估管线分裂 | 两条管线并存，统一选择全量协议做主力 | 论文可同时展示两张协议表 |
